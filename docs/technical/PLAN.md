## 第五阶段 音乐与推歌

| 任务 | 交付物 | 验收标准 |
| --- | --- | --- |
| T20 网易云能力验证 | 现成 API 验证报告及必要适配范围 | 确认运行时、授权、目标歌单权限、歌曲信息和写入返回结果 |
| T21 音乐展示 | 现成组件或官方可用入口，配置精选歌曲与共享歌单 | 展示与播放能力区分；未获得播放地址时仍能跳转网易云 |
| T22 推歌提交 | 现成提交服务配置或最小接口，记录昵称、歌曲及理由 | 有输入验证、持久记录与成功失败反馈；身份方式若变化先解决待确认项 |
| T23 推歌审核 | 优先配置现成管理或审核流程 | 管理员可通过、拒绝及查看处理状态；未通过推荐不会自动写入歌单 |
| T24 自动同步 | 现成任务执行能力与网易云 API 衔接，补充必要结果校验和重试 | 通过审核后能自动添加至实际共享歌单；重复处理不会重复添加 |
| T25 播放器和音乐交互 | 优先采用成熟播放器或现成跳转方案 | 用户播放操作有效；站内切页后的状态经过验证；不虚构完整播放能力 |

同步的拟实施状态：

- reviewStatus：pending、approved、rejected。
- syncStatus：notRequested、pending、succeeded、failed、needsAuthorization。
- 审核通过时才创建同步任务。
- 同一目标歌单与歌曲的重复请求要有一致的处理规则。
- HTTP 成功不代表网易云业务写入成功，要检查业务返回值或读回结果。
- 重试次数受控；授权错误提供管理员处理入口。
- 推荐记录和同步任务采用持久存储，不能依赖云函数临时文件。

第三方接口不可用时可以先交付网站其他模块，但音乐自动同步保持未完成，记录具体阻碍和下一步。

## 构建处理约定

优先配置框架、插件和平台已有的构建钩子与工作流。以下是需要完成的处理事项，实际执行顺序遵循所选集成；已由插件执行的步骤不额外重复运行：

1. 校验内容字段、ID、引用、资源大小和发布状态。
2. 处理有变化的图片和 PDF。
3. 使用原生链接和成熟校验或引用工具处理内容引用；只对未覆盖的业务关联补充适配，并排除未发布内容。
4. 运行 Astro 生产静态构建。
5. 由框架集成的 Pagefind 生成搜索索引，确保索引进入最终发布目录；只有集成未覆盖的内容才另作配置。
6. 核对产物中不存在服务端凭证和不应发布的原始资料。
7. 保存产物并发布至选定环境。

PDF 提取失败需要记录状态。扫描 PDF 的 OCR 可以作为后续增强，不阻止资源元信息和封面浏览。

若采用原生 Astro Actions 或 server islands，需要先调整部署方式并明确执行环境；不能把代码放进纯静态产物后期待服务端功能运行。

## 验证和交付规则

工程建立后提供 dev、check、build、preview 命令；名称可以遵循选用的包管理器，但必须与实际 package.json 一致。

针对已实现功能运行必要验证：

- 每次改动影响构建或内容规则时，执行相关类型检查和生产构建。
- 涉及知识库时，核验同主题跨类型浏览、统一检索、引用目标有效性，以及草稿在各视图中的排除。
- 涉及路由、动画、播放器和交互时，在浏览器核验切页和返回。
- 涉及外部平台时，区分模拟验证、未登录验证和真实账号验证。
- 涉及音乐写入时，验证成功、授权失效、重复任务和重试。
- 只有实际执行过的检查才能在交付中写为通过。

不编写仅复述实现的测试。优先覆盖真正可能失败的行为和各阶段验收要求。
