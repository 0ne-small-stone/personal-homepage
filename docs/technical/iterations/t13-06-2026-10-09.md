P17 / R13 / U13 / T13.06。基线 T13.05 `19ccf0a830e4c5f6bb19b09238e09f64971ca788`，分支 `codex/t13-06-save-recovery`。旧版本保存冲突与人工备份后重试实测通过，用户体验待反馈；本轮没有实现自动备份、自动合并或离开确认。

## 范围与实际改动

只操作既有 `demo-article-cms-create-check.md` 测试草稿，始终 `draft: true`，验证后恢复原文。复用成熟托管 Pages CMS，不改首页、应用源码、依赖、账号权限或网络设置。`.pages.yml` 的集合与固定文件两个 title description 增加恢复说明：先 Save 成功再离开；保存失败先备份已改字段与 Source 正文；若提示版本冲突，再刷新、对照最新内容恢复修改并重试。沿用返回列表会放弃未保存输入的真实说明。

`site.yml` 在既有 push 范围加入 `codex/t13-06-*`，真实后台保存触发原有检查，默认分支部署条件不变。设计资源新增 0，原生字段覆盖提示需求。[源码与能力边界](../REFERENCES.md#t1306-保存冲突与恢复来源2026-10-09)记录候选：重名新文件可能自动改名，不适合作为必然失败；选择旧文件 SHA 冲突，最小范围为原生说明与真实恢复验证。

## 真实后台验证

打开测试稿旧版本，在表单改标题、摘要及 Source 正文。通过 GitHub Contents API 仅推进同一工作分支测试稿的服务器标题，制造真实版本冲突；不是模拟接口返回，也不是第三方同时编辑的证据。服务器推进提交 `c9c65a540473beadd203e044d3374d78a64aab08`，blob `ff5d0d81dc08bdec4ddaf3325188c450109eb57b`。

| 操作 | 实际结果 |
| --- | --- |
| 旧表单点击 Save | 原生 Saving your file 后显示文件版本已改变、请刷新重试的错误；Save 重新可用，标题/摘要/地址/Source 正文仍为输入值，日期不变、草稿开启 |
| 未刷新直接再点 Save | 再次同一冲突错误；远程 head 仍是 `c9c65a5`，没有提交，没有覆盖服务器版本 |
| 在重载前备份输入 | 读取可见表单字段与 Source 正文保存为本机测试备份；这是执行者备份，不是 CMS 自动备份功能 |
| 备份后 reload | 读到服务器最新标题，未保存正文标记消失；证明不可先刷新再找输入 |
| 对照最新内容后填回备份并 Save | 原生成功提示，真实 CMS 保存 `e2a3b9421a971ce785213294bcaba558f3958fc7`，blob `0912e0f6e2b1eab53688779c50d2a27d381a0fde`；重开标题/摘要/标记保留、草稿开启 |
| 恢复原文并 Save | 真实 CMS 保存 `ea77f28cf69a5c550fcb78fafae038657c37a504`，blob 恢复 `889cbdef6775990adcbef093191e26c514163e0d`，与基线相同 |
| 提示推送后打开三个入口 | 集合新建、已有测试稿、固定验证稿均显示恢复说明；标题的原生 aria-describedby 关联说明节点 |

重试重开时正文连续空行经原生 rich-text 规范化，原始字符串并非逐字节相同；折叠连续空行后正文一致，标题/链接/代码及独有验证标记保留。最后恢复后源文件 blob 与原文完全一致，不能把“内容保留”误记成编辑器永不改空白。

真实重试 [CI 37938630576](https://github.com/0ne-small-stone/personal-homepage/actions/runs/37938630576) 与恢复原文 [CI 37938748747](https://github.com/0ne-small-stone/personal-homepage/actions/runs/37938748747) 三项检查分别成功，Deploy 跳过。实际自动检查证明真实 CMS 保存后有构建，不用本机模拟保存代替。
