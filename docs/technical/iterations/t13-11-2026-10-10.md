# T13.11 网页关联内容选择

对应 P17/P05/P06、R13/R09/R10、U13/U09；基于 T07.05 a950901，分支 codex/t13-11-related-picker。[草稿 PR #30](https://github.com/0ne-small-stone/personal-homepage/pull/30)。核心搜索、选择、移除、真实保存与关联渲染通过执行者验证，用户体验待反馈；未合并或部署。

## 最终实现与现成能力缺口

文章集合和固定验证稿的 related 字段改为原生 select multiple，显示“类型 · 标题 · 主题”，保存既有字符串 ID 数组。两处通过 YAML anchor 共用同一份候选；41 条已发布资源、文章和笔记来自现有 46 个知识条目，5 个草稿不进入候选，不迁移内容或新建集合。

原先 reference 配置 36cb1b5 虽通过 schema，却在托管根目录只能看到三个子目录、没有候选，不能当作通过。官方 getCollectionCache 按 parentPath 当前层读取，subfolders 只支持目录导航；0af3470 撤回查询集合，使用原生 select 和 45 行候选生成。仅复用已安装 Astro Markdown 的 parseFrontmatter，不增加依赖、后台服务或前台组件。

npm run cms:sync-related 递归生成 .pages.yml 中的候选参数。新增、改名、修改主题或上下线内容后，开发者需拉取并运行该命令，提交配置；npm run check 拒绝过期候选并提示命令。后台保存草稿或只改关联不需要同步。此边界意味着候选尚非自动实时更新；原生控件也不能按当前文章动态排除自己，说明提示不要选自己，既有前台解析继续排除自指/重复。
