## 本片选择与范围

既有服务是 Node HTTP/Connect 中间件，继续复用这套接入方式。使用已经由网易云 SDK 间接安装的 `body-parser` 2.3.0 与 `send` 1.2.1（MIT，Node >=18），显式锁为开发工具依赖，不增加前端运行依赖。

- `body-parser` 替代主音乐预览三处及推歌服务一处手工流读取、UTF-8 拼接与 JSON 解析；保持 1/2/8 KiB 上限、只接受对象、同源门禁与明确 400/413 反馈。压缩请求不接收，解析错误不回传原始请求内容。
- `send` 替代两服务的静态文件 `readFile` 和 MIME 映射，复用流式发送、HEAD、Range、类型和断连清理；保持同源/Host 检查、无缓存及点文件拒绝。
- 提取共用 JSON 响应与 Origin 判定。账号、SDK 操作、推荐审核/同步、128 MiB 音频上传、已验证本机音频映射及私有文件指纹门禁保留。
- 当前接口规模不需要新增 Hono/Express 路由层。私有音频仍经原索引和目录校验；不将整个下载目录交给通用静态目录服务。
- 推歌服务增加可注入 store/adapter 的服务器工厂，以模拟接口验证 HTTP 行为；命令行入口继续监听原 4348 端口。

## 验证安排

对真实 Node 服务验证分片中文 JSON、字节限制、畸形/空/数组输入、未知接口、Origin/Host 拒绝，以及静态首页、深路径、HEAD、Range、点文件和目录逃逸。运行既有音乐回归与仓库检查；不向真实歌单写入、扫码或重启 61173/4348 共享服务。

## 官方来源

- [body-parser](https://github.com/expressjs/body-parser)：流读取、字节限制、严格 JSON 与错误类型。
- [send](https://github.com/pillarjs/send)：编码路径、根目录、HEAD/Range、流事件与错误处理。
- [Node HTTP](https://nodejs.org/api/http.html)：沿用现有 IncomingMessage/ServerResponse 接入。
