# PDF与照片墙加载性能审查（2026-10-17）

用户反馈PDF和照片墙打开慢，要求审查结构、代码质量和依赖关系。本轮从已发布main 91ed8f8接续，并合入f7d6e63的PDF侧栏返回箭头，保留其交互与提示。修改位于独立验收工作树；共享目录已迁移到E盘，桌面入口是Junction，负责人WIP与未发布候选保留。范围为P05/T08–T09与P10/T12、T26–T27；未整合F06、Afterimage、P14候选，也未启动F04/F07。

## 结论与原始证据

照片墙把“看得到、可交互”与“空间高质量纹理就绪”拆开，受控冷启动从约6.5秒降至1.9秒。PDF消除初始化串行等待，并以原生PDFDataRangeTransport接入首屏结构分片，绕开Pages对186MB原文件单个范围请求约10.7–21.7秒的等待。原生PDF.js仍负责解析、绘制、目录、搜索、历史、下载和沉浸控件。

本机原始JSON、请求/范围、截图、失败轨迹、测试与构建日志位于项目本地忽略目录`.ci-tmp/pdf-gallery-performance-2026-10-17/`。测试为Edge、SwiftShader、模拟CSS宽度；性能对照为冷缓存、9Mbps、100ms延迟、4倍CPU节流，不冒称真机或现场Core Web Vitals。公网前后结果和部署SHA在本PR的最终验收更新读回；本记录的数字明确区分本机与公网。

## 结构与关系审查

| 问题 | 影响与改进 |
| --- | --- |

| PDF worker启动被偏好/界面初始化串行阻塞 | 在webviewerloaded时并行准备原生worker和可选分片；文档复用同一worker，非BFCache离页先关闭原生文档任务再释放worker |
| 原大PDF的206响应等待主导首屏 | 初步测得Release响应快但无浏览器CORS，未采用。改为同源、小体积、SHA绑定的首屏结构镜像；完整PDF保持原URL与字节，未知/缺失/损坏镜像回到原生请求 |
| 部分PDF首次打开要读远处目录和页面树 | 冷启动记录五份原件所需范围，按整份SHA冻结于`content/pdf-first-page-ranges.json`；与首2MiB/末256KiB合并，生成535文件、34,667,142B，避免只缓存文件头尾却漏掉结构数据 |
| 原生PDF启动未await open，失败产生额外未处理拒绝 | 适配层将失败交给现有documenterror/重试UI；不修改上游阅读器实现 |

新职责分离：`gallery/loading.js`只管可取消的图片准备；`scene.js`负责场景状态与有限GPU准备；`prepare-gallery-previews.mjs`生成并校验衍生图。PDF的`lssh-load-config.js`只适配原生入口，`lssh-range.mjs`提供可选字节范围；`prepare-fast-pdfs.mjs`只生成批准原件的镜像。没有增加框架、运行服务或npm依赖，锁文件保持。

## PDF范围边界

镜像按64KiB对齐，路径绑定sourceId与整份SHA；元数据限制64KiB、每文档最多512分片。每片字节与SHA核对，最多4并发、最多64块/4MiB传输缓存，交付原生前复制缓冲避免worker转移破坏缓存。首片或身份失败放弃加速；后续片失败使用严格Content-Range和长度验证的原件206。完整下载/未镜像大范围保持原件请求，远页所需额外数据仍可能受原站速度限制。新版本原件必须重新采集结构范围；旧SHA不允许误复用。

五份大文件（4.7MB至216MB）本机实际第一屏全部启用镜像，首屏阶段没有原件PDF请求；每份均实际跳到末页完成绘制。较小PDF保持原生传输；独立阅读器也携带注册身份。镜像增加约34.7MB静态空间，不复制整份大文件。

照片墙“就绪后1秒”记录的完成/已接收请求字节由4,393,166B降至桌面944,015B、窄屏765,720B；这是首屏窗口，不是完整空间的最终总量。640px空间层仍会随后下载，原画质保持。PDF worker的网络并未全部出现在主页面CDP字节统计中，不将该统计冒充PDF总下载量。

## 公网补优化：集中传输分散的页面结构

PR #72已保护合并为2ed0951，Pages流程39025323066部署成功。相同冷缓存/9Mbps/100ms/4倍CPU条件，公网照片墙15,987→3,232ms（79.8%），186MB教材38,013→6,425ms（83.1%）。公网32项交互、五份大PDF首屏/末页通过，首屏原件请求均为0；1275文件发布包摘要核对成功，37份PDF、535镜像和108照片资产精确一致，4份关键文本按换行规范比较一致。69份冻结源未漂移。

公网五份功能批次发现先秦导读仍用37,100ms打开；对该旧分片版本追加同条件独立测量为44,807ms。本机同条件分片版25,599ms。该教材初始页面树涉及352个分散区块；单片镜像仍有大量往返，因此增加可选连续包，不把这一慢点隐去。

仅分片数超过128的已注册首屏结构生成连续包，当前仅先秦导读：23,945,180B；535单片/描述文件继续保留。总体536文件、58,612,471B。包的文件名、总长度、整包SHA以及每片对应关系均校验；最多32MiB源缓冲，流式写入一个预分配数组，避免另留整包分段数组。常规传输缓存仍4MiB；浏览器网络/crypto/原生PDF解析另有内存，不把源缓冲上限冒称整页内存峰值。

先准备独立首片，包与worker并行；其后范围从同一包读取，交付前仍复制。45秒无新数据、缺失、截断或SHA失败回退单片，再沿原策略回原件。更新入口及元数据版本防旧缓存；完整下载和其他PDF保持。正常首屏由约355次素材请求变为3次（描述、首片、连续包），代价为增加约24MB静态空间，626,962,637B本机产物仍在现有限额内。

本轮142项风险测试通过；166文件零错误/零警告、3条既有vendor提示；54路由/55HTML构建。实际浏览器正常首/末页只请求1包+1片，原件0；包404/损坏回到354片完成首/末页，加载中离页释放worker且无迟交/脚本错误。公网最终结果记入对应补优化PR与本地验收记录。
