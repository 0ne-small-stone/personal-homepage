## 3. 保留现有框架的实现方式

### 3.1 DOM 内容与单个图形场景

保留 Astro 静态多页和 Starlight 知识库。首页采用 **静态 DOM 内容层 + 单个 React 图形 island + 单个 Canvas**。

建议按现有目录习惯落位，不要求机械照抄文件名：

```text
src/pages/index.astro                 静态身份、章节语义、真实链接
src/layouts/HomeLayout.astro          首页固定层与样式边界
src/components/home/
  HomeHeader.astro                   LSSH、三个栏目、辅助控件
  HomeChapter.astro                  章节标题、说明、图片和 CTA
  HomeJourney.tsx                    加载、质量档、场景生命周期
  GlassTriangle.tsx                  几何、透射与指针姿态
  SceneLighting.tsx                  环境亮面与章节光照
  RisingWall.tsx                     白砖墙整体升起
  home-chapters.ts                   稳定章节 ID 与路由/素材配置
```

页面内容在服务端输出。图形区可使用 `client:only="react"`，但不能把全部链接、标题、加载降级和留言入口都放在仅客户端渲染的树里。JavaScript 未运行时，静态章节仍按顺序可读可用。

视觉叠层与语义层共享同一份章节数据。透明或隐藏的视觉副本必须不可点击、不可聚焦；装饰 canvas 和扰动文字不产生重复无障碍名称。键盘到达章节控件时，对应内容必须可见。

### 3.2 最小新增依赖

1. 官方 `@astrojs/react`、React/ReactDOM。
2. `three`、`@react-three/fiber`，Drei 仅用于采用的成熟材质或辅助组件。
3. `gsap` 与 ScrollTrigger，负责与原生滚动关联的同一条场景进度。
4. 首页字体采用 SYSTEM 指定的 IBM Plex 来源和 Fontsource 本地构建方案；只加载实际用到的字族、字重和字符范围。

安装前核对实际 peer dependencies、当前版本、许可与 Astro 兼容性，再写入锁文件。[R3F 安装说明](https://r3f.docs.pmnd.rs/getting-started/installation)明确 Fiber 9 对应 React 19，Fiber 8 对应 React 18；本轮优先核对 React 19 / Fiber 9 的兼容组合，不把任意最新版混装视为通过。

不迁移主框架或改用 Swup。用户要求交互复刻后，已确认需要 Lenis 对应原站的平滑输入；采用一个实例并接入现有时钟，版本/许可/嵌套滚动在实施时验证。无须同时添加 Motion、Anime.js 或完整 UI 套件。切页由 Astro 能力适配；若需 ClientRouter，单独验证生命周期与学习区兼容性。

### 3.3 复用顺序与必要自研

先使用成熟透射材质、参数化倒角几何、环境亮面、ScrollTrigger 和普通 DOM/CSS 控件。GLSL 只补成熟方案经同画面对照仍无法覆盖的效果。

- 三角体采用 CONCEPT 中原创三角玻璃环，不复制 ALCHE 字母 A 的外轮廓，不替换已经批准的 LSSH 字标。
- 用 Drei MeshTransmissionMaterial 等成熟组件起步，先让轮廓、厚度、环境和后方内容成立，再处理色散与局部光迹。
- **WebGL 材质不能直接折射普通 DOM。**需要被折射的图像、视觉字标或图形应有场景纹理副本，按钮和语义名称继续保留 DOM。不得用截图整个 DOM 的方案掩盖内容可访问性或字体问题。
- 若画面达不到标杆，先记录缺口属于几何、背景采样、厚度、色散、流体还是时间编排。最小自写 shader 可限定为场景颜色缓冲采样、法线扰动、通道偏移或指针速度场；保留成熟材质回退，不重写完整渲染引擎。
- 不把 ALCHE 的公开 JS、模型、图片、音频或商业字体下载后当成可复用资产。研究其技术与行为，实际依赖和素材分别核对使用条件。
- 所选 React Bits、Uiverse 等社区片段若有帮助，只复用本轮缺失部分，记录具体来源及改造；不能以套件数量代替效果质量。

## 4. 滚动、加载与内容约束

### 原生滚动与状态

真实纵向文档位置是章节进度来源；Lenis 处理桌面平滑，ScrollTrigger 读取并行进度与事件，对象保留各自的原站追随系数。不要累计 wheel 次数或锁成翻页；Space、PageDown、原生触摸与修饰键保留正确路径；输入框、展开层和 Giscus 区域不控制镜头。

章节采用 `intro / projects / radio / album / links / wall` 稳定 ID。四入口共用作品弧线浏览区，并按原站配置可被新输入中断的局部吸附；各区间与参数来自 SYSTEM。向下和向上沿同一轨迹运行，停下经过追赶后可读，链接按下立即反馈。

### 加载失败时开放普通浏览

加载层只等待首屏关键资源、触发器准备、编译尝试与可呈现首帧，不等所有章节媒体。进度不可精确计量时用阶段文字，不伪造下载百分比。用户要求复刻后，加载描线的有限时间编排按 SYSTEM 执行；保留立即可用的普通浏览，不复制原站进度覆盖与错误吞掉的问题。

普通浏览入口立即可用；超时、资源错误、WebGL 不可用或 context lost 时按 SYSTEM 切到静态内容。保留有界的重试操作，不永久遮挡页面，不无限重建上下文。首帧完成不能抢走用户已经移到导航的焦点。

### 真实路由与资源地址

| 入口 | 目标 |
| --- | --- |
| Becoming | `sitePath('knowledge')` |
| Elsewhere 与网站章节 | `sitePath('links')` |
| Someone | `sitePath('about')` |
| 项目章节 | `sitePath('showcase')`；有真实作品后可指向规范详情 |
| 音乐章节 | `sitePath('music')` |
| 相册章节 | 建立 P10 实路由，再使用 `sitePath('gallery')` |
| The Wall | 首页留言区与 `sitePath('guestbook')` 的同一留言来源 |

`sitePath()` 用于路由，会追加尾斜杠；不能直接处理字体、图片、模型和音频文件路径。资产使用构建 import 或专门尊重 `BASE_URL` 的 helper。验收必须覆盖 GitHub Pages 项目前缀，不能只看服务器根路径能否打开。

封面优先真实个人素材。2026-10-08 用户允许先用专辑图等作占位：按设计 REFERENCES 的“首页专辑图占位”复用已有官方图像样本，完整来源与本地文件已提供；不必等待个人素材。将占位图片和说明作为可替换数据输入，DOM 与 WebGL 使用同一优化后的资源及明确的尺寸比例。占位不能写成个人项目、摄影或访客留言；现有介绍与新图片不匹配时同步调整占位说明。音乐入口不等于已经具备播放和歌单同步，首页不得出现虚假播放状态、频谱或同步成功。外链是实际可打开的目的地，不用空链接冒充控件。

## 6. 真实留言的接入边界

Giscus 是已经确定的提交、登录、回复与管理方案。施工前核对公开仓库、Discussions、Giscus 应用、分类与映射的实际状态；未配置时保持明确状态，其他首页切片继续推进。

- 优先验证原生 Giscus 完整闭环，再做砖墙数据映射。不要尝试跨域读取 iframe DOM 或将 iframe 样式能力当成无限可定制。
- 砖墙若需要真实留言摘录，可由 CI 读取公开 GitHub Discussions 并生成构建快照；按稳定留言 ID 排列，不随机洗牌。
- 说明快照更新时间；提交成功只表示讨论已提交，不代表当前砖墙已经刷新。处理编辑、删除、同步失败和可用原讨论定位。
- CI/服务端保管读取或写入需要的凭证，前端不出现令牌。访客身份沿用 GitHub，常规留言直接公开，不恢复旧的匿名审核方案。
- 若外部配置存在确实无法自主完成的阻碍，报告已验证的具体缺项和所需用户动作；保留可体验首页和真实失败入口，不标记服务已经接通。

## 7. 生命周期、媒体与性能

### 生命周期

当前普通多页导航先处理 `pagehide/pageshow`、BFCache、页面可见性与 resize；React 效果及资源应有明确清理职责。取消未完成的加载，移除监听，停止时间线与音频可视化，释放独占材质、几何、纹理和缓冲；共享缓存避免重复释放。

若后来采用 Astro ClientRouter，再验证 `astro:before-swap` 清理与 `astro:page-load` 幂等恢复，不仅监听 DOMContentLoaded。不能为了保持场景把 Canvas 无条件持久化到所有知识阅读页。

返回状态遵循 CONCEPT 的 `{chapterId, localProgress, scrollY, focusOrigin}`；使用命名空间保存并保留框架现有 history state。不能每帧新增历史记录。直接深链无首页来路时，返回控件仍有明确所属栏目。

### 媒体与质量档

- 通过 Astro 图片处理或等效构建流程生成合适尺寸与格式，语义图片有尺寸、alt 和失败状态；不要直接把大型品牌母版和原照片都塞进首屏。
- WebGL 纹理与 DOM 图片使用同一素材登记，明确色彩空间、裁切和派生关系，避免“双份原图同时下载”。
- 章节媒体按接近程度加载，图库、播放器、Giscus 按实际入口加载；首屏不预载完整音乐和相册。
- 采用 SYSTEM 的 DPR、透射缓冲和采样起点，记录实际设备和帧时间；先量测额外 render pass，再启用双面透射或后处理。
- 页面隐藏时暂停不必要的渲染和音频可视化；减少动画/暂停动态关闭自转、扰码与流体。触屏取消指针视差，维持原生滑动。
- 声音只有真实且可使用的音源准备好后才能开启；用户主动开启才能播放。环境音状态与音乐电台状态分别管理。

## 8. 每片验证与最终交付

依改动范围执行 `npm run check`、`npm run build` 和仓库文档检查。安装依赖与构建通过后仍必须在实际浏览器体验，不能用日志代替视觉和交互证据。

最终至少覆盖：

1. 带 `/personal-homepage/` 前缀的首页、栏目、相册、guestbook、字体和媒体；普通深链、刷新、404 与外链。
2. 首次加载、缓存命中、关键资源错误、超时、普通浏览、重试，以及中途点击顶栏离开。
3. 原生滚轮、快速滚动、反向、触摸、键盘与章节锚点；文字与 CTA 的稳定可用窗口。
4. 首页 → 每个实际栏目 → 后退；回到序章不重载；直接访问栏目不要求播放首页。
5. 终章升墙后正常阅读和输入；打开/关闭留言或菜单恢复焦点，场景不抢点击与滚动。
6. 桌面与手机、文字放大、字体加载前后和实际设备回退；无横向溢出或固定顶栏遮挡。
7. 无 WebGL、context lost、无 JavaScript、减少动画、暂停动态；所有内容入口继续可用。
8. 多次离开/重新进入后的 Canvas、事件、RAF、纹理和音频状态；后台暂停和 BFCache 恢复。
9. 按 SYSTEM 目标采样实际性能，并对比黑底稳态、转场关键帧、白墙末帧和低性能质量档。目标与通过结果分别记录。
10. Giscus 的未登录、真实登录/提交、服务不可达与快照延迟；不能通过示例数据宣称真实服务已验收。

每片交付记录：P/R/U/T 编号、唯一主要目标、改动文件、实际体验 URL、复现步骤、浏览器与设备、截图/关键帧/必要录屏、检查结果、提交/PR、未解决项和下一片。审美待用户体验可以单独保留；已授权的常规实现和修复继续推进。
