# P01 · 玻璃近黑根因与透射色调映射诊断

日期：2026-10-08。P01 / R01、R12 / U03、U05 / T03.05。承接 [23 轮反射基值样本](u03-p01-2026-10-08-23.md)。本轮为设计侧隔离诊断，应用修正仍交由首页开发。

## 结论

**已证实一个直接导致黑框的原因：背景直出关闭了 tone mapping，玻璃透射却额外应用 ACES，把同一深灰背景压到接近黑色。**

保持 `.015` 反射基值、环境、几何、法线、相机、姿态和背景不变，只在浏览器响应中去掉玻璃的 ACES 输出步骤，桌面正面和 35° 视角的面内灰值从约 `1–2` 恢复到 `10–15`（8 位 RGB 均值），砖墙层次重新可见。两视角的全部玻璃外像素均完全一致。

环境纹理实际已接入，也有真实亮区。它不是空纹理；本次六个 cube 面最高线性通道均值为 `.688965`，低于现有 `.85` 上限，故这批画面也不能归咎于该裁切。当前宽面所取方向的环境输出仍很暗，柔和高光尚未达标；**修复色调路径不等于最终玻璃设计通过**。

## 运行时证据与原因链路

实际读回：`uEnvironment` 等于 `reflectionScene.environment`；对象为 `isCubeTexture=true`、`isRenderTargetTexture=true`，128px × 6 面，HalfFloat（type 1016），NoColorSpace。没有落到初始化的 1px 黑色 fallback，也没有误选共享主场景环境。

| Cube 面索引 | 线性 RGB 均值 | 线性 RGB 最大值 |
| --- | ---: | ---: |
| 0 / +X | .009981 | .343750 |
| 1 / −X | .014908 | .424561 |
| 2 / +Y | .002460 | .017639 |
| 3 / −Y | .006733 | .083740 |
| 4 / +Z | .053660 | .553223 |
| 5 / −Z | .031766 | .688965 |

这些数值是实际 GPU 半浮点纹理读回，不是灯箱参数推算。全 cube 有亮区并不表示当前正面法线的反射方向取到了亮区；宽面反射仍暗的问题保留给修正色彩路径之后。

实际 renderer 为 toneMapping `4`（ACESFilmic）、曝光 `1`、输出 `srgb`；`uScene` 为 512×320 HalfFloat / NoColorSpace。源码链路如下：

- `SceneBackdrop.tsx` 的 CanvasTexture 标为 sRGB，材质 `toneMapped=false`，砖块颜色为 `#111` 到 `#050505`。
- `GlassOptics.tsx` 采集 FBO 时设置 NoToneMapping，随后恢复 renderer；这是正常的线性缓冲采集，不能据此认为玻璃最终输出也跳过了 ACES。
- 新建 ShaderMaterial 没有指定 `toneMapped`，本地 Three `Material` 的默认值为 true；玻璃随后执行 `tonemapping_fragment` 和 `colorspace_fragment`。
- 本地 Three 的 `WebGLPrograms` 只在最终屏幕输出且材质开启时应用 renderer tone mapping，普通 FBO 使用工作色彩空间。HalfFloat / NoColorSpace 并不等于遗漏一次必须的 sRGB 解码。

令 D/E 为 sRGB 解码/编码，则背景大致为 `E(D(s))`，玻璃则为 `E(ACES((1−w)T+wR))`。同一背景经过了不同的显示变换。准确说是玻璃额外应用了一次 ACES，**不是声称 FBO 已做过 ACES 又被重复做了一次**。

独立只读代码核对使用本地 Three `0.186.1` 的 `Material.js`、`constants.js`、`WebGLPrograms.js`、`tonemapping_pars_fragment.glsl.js`。其曝光 1 的中性灰公式表明，忽略反射及采样偏移时，显示灰 `#050505` 经此 ACES 可到 0，`#111111` 可到约 3；亮光束仍可见。这与通道图一致，真实像素证据以下表为准。

## 给首页开发的唯一修正任务

**目标：让当前背景经玻璃透射后保留本来的深灰层次，消除额外 ACES 造成的黑色填充感。**

1. 仅在 `GlassOptics.tsx` 创建 ShaderMaterial 时显式设置 `toneMapped: false`，使这条现有背景合成路径与 `SceneBackdrop`、背景标题材质一致；保留 `colorspace_fragment`，不全局关闭 renderer tone mapping。现有 tone mapping chunk 可保留，由材质开关让它不应用 ACES。
2. 保持 `.015 + .82 × edge`、`.85` 上限、环境分布、法线、折射、几何及章节动作不变；`.06` 仍未采用。
3. 先复用本轮两种固定视图验证：砖块穿过环体后仍能辨认其层次，标题/光束仍折射，不变成均匀灰板；玻璃外控制区无变化。再在实际页面确认未出现 shader 错误。正常类型检查和生产构建由开发侧执行。
4. 将这一片记录为“透射颜色路径修复”，独立于下一片宽面反射。当前弱高光不靠继续调曝光掩盖；修复后再用正确基线决定环境采样方向或法线是否需要单独处理。

本轮没有替开发实施这一修正，也没有宣布最终玻璃或完整首页完成。主设计负责发送任务给用户指定的首页开发对话。
