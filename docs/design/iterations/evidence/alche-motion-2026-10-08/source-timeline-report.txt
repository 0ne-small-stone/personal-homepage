## 1. 最重要的控制关系

[S] 原站没有一条贯穿首页的 GSAP master timeline，也没有自定义命名 timeline label。主机制是：

`wheel → Lenis 平滑后的真实 scrollY → 多个并行 ScrollTrigger.progress / enter事件 → 自定义 Lerper、Animator、GSAP小动画 → 多场景合成`。

ScrollTrigger 给出“文档已经走到哪里”；图片/相机继续追赶平滑目标；标题在跨阈值时按秒播放；snap 在停滚条件满足后移动文档到吸附点。因此即使相同 scrollY，刚停滚与停稳后的画面不同。不能只采一张 progress 静帧就认为节奏已复刻。

[S] 首页 `TopScrollManager` 中所有主 trigger 都没有 `scrub`、`pin` 或 `animation` 字段；它们主要产出 progress、事件和 snap。CSS 用 fixed/sticky 保持画面，GL 每帧直接取 trigger.progress。`WorksOutroController`、`OutroController` 的附加 trigger 也不是 scrub。

## 4. Lenis与逐帧平滑：精确参数

[S] Lenis **1.3.4**，唯一首页构造为 `new Lenis({})`，即使用bundle该版本默认值：wrapper=window、content=document.documentElement、smoothWheel=true、syncTouch=false、lerp=.1、duration/easing未指定、orientation=vertical、gestureOrientation=vertical、wheelMultiplier=1、touchMultiplier=1、infinite=false、overscroll=true、autoResize=true、autoRaf=false、anchors=false、allowNestedScroll=false。syncTouchLerp=.075、touchInertiaMultiplier=35虽然存在，但syncTouch=false时不能称为已启用的触摸平滑参数。

[S] 原站主RAF顺序：`lenis.raf(timestamp)` → `gl.update()` → `lerper.update(timestamp)` → indicator/sound/loading更新 → requestAnimationFrame。未找到`lenis.on('scroll',ScrollTrigger.update)`连接；ScrollTrigger仍靠真实滚动事件更新。document.hidden时停止主RAF，恢复可见后启动。GL内部动画deltaTime最大1/30秒；Lerper用RAF实际时间差，没有这个上限。

[S] Lenis默认damp：`animated += (target-animated)*(1-exp(-6*dt))`（因为lerp*.60=.1*60=6）。这是每帧指数追赶，不是固定1秒滚动。单击侧边章节/子点则明确调用`lenis.scrollTo(target,{duration:1.2,easing:t=>min(1,1.001-2^(-10t))})`，改用按时长滚动。

[S] Lerper：第一次set直接current=target；后续set只写target并返回此前current。每帧update：`velocity=target-current; current += velocity*min(1,dt*10*multiplier)`。这里velocity是误差量，不是每秒速度。主要参数：

## 5. 玻璃体与相机：无需猜keyframe

### 固定构图和设备插值

[S] `TopPageMainScene`给MainLogo对象scale=4.3，position=(0,-.3,0)；加载Alche_A mesh后局部scale=3，即嵌套缩放4.3×3。`spWeight=clamp01((16/9-aspect)/(16/9-9/16))`，不是简单≤768二值。LayoutController把mainLogo.y线性加`.5*spWeight`；背景2D Logo位于z=-15，手机趋向y=1、scale×.55。WorksThumbnails组手机趋向y=.8、scale×.6。

[S] 主相机base=(0,0,10)，`baseFov=35+18/aspect`；`kvZoom`初值1，在kv目标1，离开kv目标0，Animator均1秒：相机z=`10-.5*kvZoom`，FOV=`baseFov-4*kvZoom`。1440×900时baseFov46.25°，首屏42.25°/z9.5，非首屏46.25°/z10。每帧lookAt(0,0,0)。

[S] 鼠标NDC=(2x/W-1,1-2y/H)；相机offset目标=`NDC*.5*(1-L(works_outro,.5))`；offset自身用`lerp(alpha=min(3dt,1))`追赶。作品尾段逐渐把视差归零，避免亮场继续漂移。

[S] works_outro [6400,7750] 内，GL最后把主相机projectionMatrix的16个元素线性混到mission orthographic projection；目标正交短边±4，长边按aspect扩展：横屏left/right=±4aspect、top/bottom=±4；竖屏left/right=±4、top/bottom=±4/aspect。不是仅调fov，也不是把camera.position一路推近。MissionScene自带perspective camera虽有(0,0,8),fov60的声明，但render实际使用main camera；正交相机仅提供目标矩阵。

### 自转、滚速、指针与回正

[S] glass mesh四元数每帧依次premultiply鼠标四元数、绕Y旋转四元数，再slerp回identity。worksRotate按section切换，Animator默认归一化sigmoid(k=6)，1秒。

| section config | intensity | base yaw speed | return force | scroll factor | hover multiplier |
|---|---:|---:|---:|---:|---:|
| default |0|0|2|0|0|
| kv |0|0|2|0|1|
| works_intro |1|.5|.4|.001|.2|
| works |1|.5|.1|.001|.2|
| mission |0|0|2|0|0|
| vision |0|0|1.5|0|0|
| service（定义存在，常规items实际发service_0/1）|0|0|1.8|0|1|

实际yaw增量：`-dt*baseSpeed*worksRotate - L(clamp(lenis.velocity,-30,30),.5)*scrollFactor`。第二项**没有再乘dt**。回正系数：`dt*returnForce*(1-.8*worksRotate)`。因此works自动旋转、滚动加速/逆滚反向，停下后仍转；kv仅指针拨动后回正。

指针旋转强度`m=.01*max(0,1-1.5*length(NDC))*hoverMultiplier`；用Lerper误差vx/vy改变临时Euler：`x-=vy*m*(1-.7*worksRotate)`、`y+=vx*m`；临时Euler每帧乘`1-dt`。中心附近响应最强，NDC半径≥2/3时这一手势驱动力为0；相机视差仍可存在。不要把此效果写成“离中心越远转得越多”。

### 亮场轮廓到服务侧屏

[S] Mission/Vision场景包含玻璃轮廓容器，matrixWorld逐帧复制原glass mesh。顶点shader额外对局部xz旋转`(.15*visionProgress+.5*serviceRotate)*π/2`，yz旋转`-.1*visionProgress-.2*serviceRotate`。接着将正常投影位置和侧屏clip-space位置按serviceRotate线性混合；侧屏目标从原geometry转90°后构造：`x*(20.5+3/aspect)`、`y*(7+8aspect)-.22`。这是侧面持续铺开，不是一张DOM图opacity渐变。

[S] SideScreen采样rtServiceScene；uServiceIn越大，UV从窄几何uv向screen UV转（权重pow(serviceIn,.2)），噪声位移、RGB镜头畸变、额外亮度逐渐降为0。screen alpha=`smoothstep(0,.1,visionProgress)`，Vision刚开始即出现内部噪声/内容。最终scene mixer到serviceIn≥.9999才硬切到全屏service render target；此前内容通过侧屏渲染持续扩张掩盖切换。

## 6. WORKS：卡片沿弧线、曲面、标题、背景分别运行

[S] 6卡共用works_progress。令`p=L(works_progress,1)`，`o=7p`，`r=round(o)`，`u=L(r+.4*(o-r),.5)`；debug模式才绕过第二层令u=o。第i张卡(i=0..5)令`d=i+1-u`：


[D] 卡片在中心d=0时(x,y,z)=(0,0,-1)，桌面局部scale1.1；d=±1时x≈±9.256、y=∓1、z≈-3.298、rotation≈±34.38°，scale.9。不是等速横向carousel；卡片离中心后绕到后方并略向上/下偏移。u在半整数附近被round目标推向下一整数，形成停驻与切换感，再由二层平滑消去目标跳变。

[S] 局部mesh来自GLTF的`ThumbnailScreen`，失败时才用8×4.5×.1、16×16分段BoxGeometry。顶点固定曲面：`z=.2*z + 1.5*cos(x*π/16)-1`。图片按16:9 cover裁切。fragment每通道4次采样，镜头distortion系数R=.2+.03i、G=.22+.03i、B=.24+.03i（i=0,.25,.5,.75），加normal方向采样偏移；边缘暗化、最终alpha乘loaded×alpha。图片加载后loaded在1秒内渐显。

[S] **滚速曲面误读要排除**：顶点中`uScrollVelocity*0.0`使“随速度挤压”项为0；fragment的`moveUVOffset.x-=uScrollVelocity`算出后没有使用。uPosX虽被传入，却不参与最终图像采样。当前bundle能确定的是固定曲率+整体轨迹，不应描述为“滚得越快卡片越软”。

## 7. 黑/亮场遮罩与文字书写

[S] MissionVision场景背景色是 **#D7DBDC**。主场景与亮场先分别渲染，再屏幕混合。令a=亮场当前权重，v=其motionBlur变量；每帧`M=visibleMission-a; v+=(M-v)*.5; a+=M*.5`，visibleMission来自mission_in的Lerper1.5。注意v是每帧差值的滤波，不是px/s。

边缘公式（UV.y=0为画面底部）：

```
range = 1/resolutionY + abs(v)*.2
round = -cos((uv.x-.5)*π) * v * (1-.8*spWeight)
edge = v>0 ? a*(1+range) : a
mask = smoothstep(0,range,-uv.y+edge+round)
output = mix(mainSceneColor,missionVisionSceneColor,mask)
```

[D] 正向滚动从下往上揭幕，速度差越大边缘越软并出现弧度；反向滚动弧度符号反转。手机spWeight1时弧度仅桌面系数的20%。main/mission/service还各有不同径向暗角，且指针fluids对采样方向分别为+.01、-.01、+.01，产生彼此不同的波动。

[S] Mission DOM文字的CSS mask与GL边缘并行：仅桌面媒体规则用`linear-gradient(to top,black --mask-height,transparent --mask-height+--mask-fade)`；JS设height=`100*L(mission_in,1)-1.5`%，fade=3%。手机UA跳过JS mask，≤768px CSS也不设此mask。

[S] Mission/Vision SVG路径从strokeDasharray `0 500`到`500 0`。GSAP paused timeline名义duration1、ease none，实际`.progress(u)`由scroll每帧设定。`u=L(round(raw)+.7*(raw-round(raw)),.4)`，raw=L(trigger.progress,.4)。第j行阈值b=.8j/lineCount；行显现ease power3.out(clamp01((u-b)/.1))，opacity=该值，y=8*(1-该值)px；高亮marker从b+.03起、进度宽度.5、ease power2.out。正文逐行显现与背景擦除不是单一相同阈值。

[S] 桌面退出：取outTrigger.progress，g=max(0,1-2progress)，path opacity=g、正文opacity=g、英文opacity=g*u、title/正文/英文blur=(1-g)*10px。Mission的out=vision，Vision的out=vision_out。因此退出前半区间即已完全消失，后半留给背景动作。手机≤768跳过整个opacity+blur退出逻辑，改用正常DOM滚动；Vision整体opacity仍直接等于vision trigger.progress。

## 8. SERVICE到STELLLA：正弦波面与全屏铺开

[S] 服务scene camera=(0,0,10),fov50。平面网格64×64，卡片16×8，标题64×1；不是刚性CSS平面。service列表自身serviceIn=L(trigger,.3)，> .01才visible。

## 10. 桌面/手机差异与验证限制

[S] 手机判定有三个不同维度，必须保留区分：`DeviceManager.isSPLayout`是window.innerWidth≤768；GL `_isMobile`是另一个UA/iPad特判，用来禁用fluid setPointer/update；`spWeight`依照aspect连续变化。DeviceManager跨过768断点会整页reload。手机模拟视口不等于真实手机UA，不应仅改width就宣称fluid路径相同。

### 复现协议（开发与设计用同一份输入）

- 同浏览器、同viewport、同DPR、同UA、同N、同图片/裁切；先完成loading，记录load结束时间。鼠标固定viewport左上(0,0)，在同一位置稳定2秒；这样Logo中心拨动驱动力为0，并把相机偏移固定为同一基线。需要居中构图时可改用中心，但两端必须同样操作并等待。
- 每次实验从页首刷新，先静止2秒，完整执行同一方向的滚动序列；不要先跳到终点再退回起点采正向帧。动态自转由真实时间累积，所以两站都从加载结束后的同一时间启动输入。
- **I段静态五采样**：通过受控设置文档scrollY到100、325、550、775、1000（或用公式换H），每点等同样2秒；同时记录request与实际scrollY、body.current_section、时间戳。这是“停稳状态对照”，不能证明动态节奏相同。
- **A段静态五采样**：1000、1225、1450、1675、1900；中点另测1449和1451，记方向。每点至少保存到位立即、250ms、1000ms、2000ms四个时刻；识别平滑追赶与标题自播放，不能把2秒后截图称作瞬时映射。
- **动态对照输入**：固定指针后，从scrollY100开始，按记录的同一系列wheel事件（deltaY及相邻时间间隔完全相同）经过1000到1900，再反向；逐RAF或每16.7ms记录scrollY，在两个站按实际pI/q而非输入次数对齐帧。建议慢输入50px/100ms、快输入单次900px、以及越过q=.5后立即反向三条序列，先只做这段。Lenis指数追赶不能以最终total delta代替同输入过程。
- **判读**：在同一pI/q下同时比较“到该点后的时间”；卡片位置/alpha必须符合公式趋势，标题跨q=.5后启动，背景比前景用不同平滑，相机拉远完成后不要继续直线穿越。同步记录是否snap启动、视频/图像加载状态；第一卡前半alpha不应过早全亮。
