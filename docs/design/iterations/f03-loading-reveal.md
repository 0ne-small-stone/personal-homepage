| 状态 | 画面与动作 | 判定点 |
| --- | --- | --- |
| 等待 | 纯黑留白；字标放在首页最终锚点，形成安静的身份标记。下方边缘左侧状态、右侧普通浏览，沿用页面留白；中央为尚未显现的玻璃留空 | 字标与普通浏览可读，不伪造百分比、不循环呼吸、不要求资源等待满某个秒数 |

## 4. 交互与生命周期

- 状态独立为 waiting / revealing / ready / fallback（命名可遵循现有约定）。资源只报告准备状态，单一控制器启动一次揭幕并处理结束、跳过、失败与卸载。
- 等待与揭幕期间“普通浏览”始终可操作，键盘能聚焦。进入普通浏览立即终止时间线、取消后续完成回调并显示完整静态内容，不继续暗中启动揭幕。
- 页面默认内容可读；脚本不加载不应留下永久遮罩。仅加载层覆盖期间，对被遮挡控件合理隔离焦点；跳过链接保持可用。状态文本使用适度 live region，不把整幅图形/按钮包成反复播报的状态。
- 首访首屏播放一次。已访问、从栏目返回、浏览器恢复，以及非 intro 的直达 hash，恢复目标内容且不强制先滚回首屏。不要为录制效果清理用户 sessionStorage。
- 快资源直接开始有限揭幕，不补演等待；慢资源安静等待；超时和失败走静态。字标解码也需要处理失败，不能只有空白。
- 减少动画/已有暂停偏好：直接给可读页面，取消径向扭曲与轮廓长动作。按已有降级约定保留静态内容；不将该状态当作普通动态模式测试通过。
- 页面隐藏/离开中止无意义绘制；卸载及重试不会重复监听、重复 Canvas 或重复计时器。重试沿用现有一次上限。
- 普通 wheel/touch/键盘滚动在有限揭幕期若被延后，完成后不能突跳到积累输入处。用户明确的跳过/导航必须立即生效；已知深链必须优先恢复目标。

## 5. 实施步骤与边界

1. **加载构图与门槛**：对齐批准字标、状态行和普通浏览；划清准备/揭幕/可浏览状态，避免触发器等待 ready 而 ready 又等触发器的循环。先验证快、慢、失败和跳过。
2. **一次连续动作**：用现有玻璃覆盖数据显现轮廓；在单 Renderer 最终场景上做临时采样揭幕。随后实看桌面与窄屏，集中调整一次。
3. **完整 F03 候选**：做返回、直达、减少动画和 F02 最小回归，交付固定实际首页。步骤不是独立请求用户批准的三项功能；最终只交一项 F03。

不改 F02 的几何形变/向上垒墙、砖顺序、底边遮罩、材质与局部时长；章节数量变化后的全局区间沿用最新轮播调整结果。不得恢复入射光、色散/光谱、流体模拟、全屏持续 Bloom。F03 的有限径向 UV 揭幕是时间驱动图像采样，不接指针流场、反馈缓存或物理引擎。

准备时允许用实际渲染路径预热必要材质，但不能仅凭 compile 调用结束就宣称首帧成功。若可选揭幕 pass 不可用，及时走清晰的无扭曲/静态替代，记录降级，不能卡住等待。临时 target/材质退出后销毁或从绘制路径解除；原 renderer state、色彩空间、DPR/resize、已有 Portal 和玻璃层次须恢复。
