## 1. 用户决定与更新范围

用户指定 [ALCHE](https://alche.studio/) 为标杆：加载页后出现玻璃旋转三角体；滚动依次到项目展示、音乐电台、相册、常用网站的入口画面；最后 The Wall 升起成为留言墙。顶栏固定 Becoming、Elsewhere、Someone。

- 顺序与入口已经确定，不再等待重新选风格。
- 原有纯黑/中性灰、圆润克制、温柔辽阔、已确认字标与学习区苹方继续生效。
- 旧的四角光路与点击棱镜激活靠近停止作为首页默认实现；立方体研究保留历史。
- 章节是首页状态，真实内容仍通过 Astro 独立路由访问。未来 AI、知识库、音乐同步等业务范围不因本轮缩减。

现行依据：[页面规格 P01](../SPEC.md#p01-首页)、[场景与控件](../CONCEPT.md#10-alche-标杆下的现行首页场景)、[唯一参数源](../SYSTEM.md#9-p01-alche-方向的施工参数)、[开发交接](../../technical/HOMEPAGE_ALCHE_HANDOFF.md)。

## 3. 公开代码核实结果

### 3.1 基础架构

源站 HTML generator 为 Astro 5.13.3；当前主 bundle 中有 Three REVISION 177、GSAP 3.13.0、Lenis 1.3.4、Lottie、Howler、Tweakpane；路由脚本使用 Swup。源码版本与 LICENSE 页的旧依赖自述有差异，以本次实际 bundle 为观察基准。

直接来源：

- [主场景脚本](https://alche.studio/_astro/index.astro_astro_type_script_index_0_lang.Cn_goiN_.js)
- [首页样式](https://alche.studio/_astro/index.CQ0ApTUm.css)
- [导航、加载与字体样式](https://alche.studio/_astro/about.DKIoZJhT.css)
- [路由脚本](https://alche.studio/_astro/page.SNkKDTDH.js)
- [官网依赖许可](https://alche.studio/license/)

主场景文件本次 1,831,372 字节，SHA256 `b2bd0d964416bd3db61b1392d2b645314e50ea79cadb09f69755d5f4c3791853`。这些带 hash 的地址可能随网站更新改变，届时从首页重新发现，不把它们设为网站运行依赖。

### 3.2 玻璃与鼠标

原站使用 `/common/scene.glb` 中的 `Alche_A`，另有 Outline 和 SideScreen 形态。主玻璃是自定义 ShaderMaterial：先把背景渲染到离屏纹理，再按视空间法线偏移采样；RGB 采用不同偏移产生色散；噪声与多次采样形成粗糙度；立方体环境纹理、Fresnel 和高光补足边缘反射。FXAA 与低分辨率 Bloom 参与最终画面。

这解释了为什么 CSS `backdrop-filter: blur()`、半透明三角 SVG 或一张金属 PNG 不能交付同等效果。玻璃必须看到背后的场景，转动时折射与边缘随之改变。

**指针行为的区别：**首屏 `kv` 的 baseRotationSpeed 与 animationIntensity 均为 0，hoverRotationMultiplier 为 1。鼠标运动速度带来旋转冲量，距离中心影响强度，随后四元数插值回正；相机另有小幅平滑视差。到 works_intro/works，才增加基础转速与受限的滚动速度影响。它不是替换操作系统鼠标的三角指针。本站在此基础上按用户要求增加可暂停的缓转，记录为设计决定。

### 3.3 滚动、图像与黑白转换

原站一个固定 Canvas 贯穿页面，真实 DOM 段落提供滚动距离，Lenis 与 ScrollTrigger 把区间映射为进度。多个场景先写入离屏纹理，再用 shader 组合；相机、图形、图像、DOM 文案和导航主题共享章节信号。鼠标流体速度纹理产生局部扭曲。浅色段通过带弧度的遮罩展开；不是整页简单淡出再换背景。

LSSH 的实现应保留这种“一个空间承接所有画面”的连续性。项目、唱片、照片与网站承担不同构图，但都读取同一章节进度。白墙是本站终章的新设计，不能声称 ALCHE 原站有同一堵留言墙。

### 3.4 加载与声音

原站加载包含两段 Lottie、Three LoadingManager、ScrollTrigger 就绪与 shader 预编译状态；完成后中心径向揭幕并带折射缩放。声音用 Howler 管理、默认静音，保存选择；原站移动端减少了声音与流体效果。renderer 使用 DPR1，页面隐藏时停止 RAF。

本站首版用真实首屏资源状态和简洁 SVG/CSS 揭幕即可建立完整机制；字标使用已批准资产。必须预热第一帧后再撤掉遮罩，不能为了模拟加载而固定倒数。环境音、音乐电台播放与网易云同步是三个独立状态；素材或服务缺失不等于播放成功。

## 4. 字体与按钮落实方案

| 对象 | ALCHE 已确认 | LSSH 采用方式 |
| --- | --- | --- |
| 顶栏与加载 | IBM Plex Mono；桌面导航计算值 14px/400，字距 1.4px | 同一家族的官方 OFL 文件经本地字体包部署，导航与序号共用 |
| 作品大标题 | Acumin Pro 500；部分 service 用 Acumin Pro Wide | 首版用 IBM Plex Sans 的明确许可资源承担同一角色；形态差异需实际对照，不借用原站 Adobe kit |
| 日期、标签和提示 | Google Sans Code，部分数字 Barlow | 为减少家族数，统一到 IBM Plex Mono；不为每种元数据装一个字体 |
| 日文 | Kozuka Gothic Pr6N / IBM Plex Sans JP | 不搬日文栈；本站中文继续 PingFang 优先与系统回退 |
| 品牌 | ALCHE 自有标志与场景网格 | 使用已批准 little stone / still here 字标；三角体是空间物体 |
| 普通导航 | ScrambleText，短暂扰码再还原 | 一次局部字符反馈，仅视觉副本变化；焦点与减少动画保持完整可读 |
| 主 CTA | 胶囊描边，双份文字向上翻动，hover 黑白反色 | 简单 CSS 双行包装可完成；真实 `<a>` 名称不重复，不等动画结束再导航 |
| 声音 | 细柱图标与圆形按钮 | 本站最小触摸区按 SYSTEM，实际状态与 `aria-pressed` 一致 |
| 深浅导航 | 随章节切换黑/白 | 明确主题状态，稳定背景/焦点；不复制源站取消 outline 的弱项 |

原站 Acumin/小塚通过 [Adobe kit](https://use.typekit.net/ukr2yqt.js) 加载；该 kit、字体文件与授权不属于本项目。IBM Plex 使用 [官方 OFL 许可](https://github.com/IBM/plex/blob/master/LICENSE.txt)。尺寸、字距、时长只在 SYSTEM 第 9 节给出本站施工值。

## 5. 复用选择及能力缺口

| 优先方案 | 能覆盖 | 需要的最小适配 |
| --- | --- | --- |
| Astro + 官方 React island | 静态可访问页面与局部复杂场景 | 单个首页 island、语义 DOM 层和清理逻辑 |
| R3F + Three + Drei MeshTransmissionMaterial | 透射、厚度、IOR、色散、采样与环境反射 | 原创三角环几何、分层灯光、玻璃背后内容的渲染安排 |
| GSAP ScrollTrigger | 可逆滚动区间、时间线、refresh、媒体条件 | 数据化章节与对应姿态，首轮无需平滑滚动库 |
| CSS 双行按钮 + GSAP ScrambleText（按需） | 翻字、反色与短字符扰动 | 品牌字符、语义副本、触摸/焦点/减少动画 |
| Three InstancedMesh + DOM 留言面板 | 同形白砖高效绘制、语义操作 | 稳定留言 ID 与位置映射、升墙轨迹及数据来源 |
| Giscus | GitHub 身份、留言与回复 | 原生提交区域；墙砖展示另读公开快照，不抓跨域 iframe DOM |

React Bits 的 Prism / Light Rays 可以比较局部光效，但二维背景 shader 不能直接替代同一场景的透射几何；Uiverse 的普通按钮也不需要整库接入。这次具体动作已由 ALCHE 确定，Anime.js、Aceternity UI 不与 GSAP 叠加引入。原站 Swup、Lottie、Howler、Lenis 的全套并非施工前置。

如果成熟透射材质仍达不到参考，先记录同视角、同背景的明确缺口，再写最小自定义 pass：共享背景 FBO → 法线偏移采样 → 小幅 RGB 分离 → Fresnel 混合。实现思路可研究，原站商业成品 shader 与模型不直接复制。背景流体同理：先证明场景与材质，再以低分辨率速度场适配；不因增加流体而损坏可读层。

## 6. 给 AI 的执行与验收方式

开发不能只收到“参考 ALCHE 做高级一些”。每一片必须有：固定截图/原站依据、本站目标与控制编号、允许改动文件、参数来源、真实浏览路径、截图/短录屏和未解决问题。

顺序为静态导航/字体 → 单玻璃材质 → 一个项目过渡 → 全部章节 → 升墙 → 返回与降级 → 真实留言 → 有明确缺口的高级光学。完整队列在技术 PLAN 与交接单；每片执行完按下一片推进，不把写完规划记作功能完成。

视觉最低判据：

1. 静止时有完整构图，玻璃边缘、开口、厚度清楚，不能靠不停转动掩盖形体问题。
2. 玻璃后方图形随观察角度发生折射变化；既不过度乳白，也不完全透明消失。
3. 顶栏位置稳定；项目、音乐、相册、网址顺序准确，进入目标真实存在。
4. 每段五帧有连续方向，返回同一章节时画面不跳到初始状态；快速滚动不排队回放。
5. 墙整体从下方升起并落定，砖缝在白底上仍可读；没有假留言或假提交。
6. 手机、无 WebGL、减少动画仍有完整身份与全部链接；浏览器键盘焦点不在看不见的叠层中。

本轮没有改应用代码、安装网站依赖、创建 PR 或部署。用户已明确授权把具体开发任务发给「首页开发」；发送状态单独写入设计 PLAN。
