## 1. 本轮决定

用户明确纠正：“你扒 alche 还不够细，要求复刻它的交互和动画。”本轮将粗略风格参考改成**行为复刻**：同一输入下，阶段关系、运动方向、追随/惯性、停驻、反向、遮罩、按钮及手机差异有可核对的依据。

本站的 Little Stone Still Here 身份、四入口顺序、黑灰与末段 The Wall 继续沿用。下文分别标注原站事实、本站映射、公式推导与未完成验证；不把文档完成当成网站已经复刻。

**施工入口：**[SYSTEM 9.2](../SYSTEM.md#92-运动与滚动) 是采用参数的唯一来源；[CONCEPT 10](../CONCEPT.md#10-alche-标杆下的现行首页场景) 管内容与空间映射；[开发任务单](../../technical/HOMEPAGE_ALCHE_HANDOFF.md) 管实现顺序和门禁。第 10 轮的额外首屏缓转、简化揭幕与无需平滑库等建议已被替代。

## 3. 与此前理解的关键差异

| 对象 | 本轮确认的实际机制 | 对现有首页的直接改动要求 |
| --- | --- | --- |
| 总体滚动 | Lenis 的真实文档位置 → 多个并行 ScrollTrigger 进度与进入事件 → 对象各自平滑/按秒动画 → 场景合成；主 trigger 无 scrub | 取消“一章一个等长进度+共用淡入”；建立明确通道及阶段边界 |
| 首屏与作品 | 序章、作品标题引入、首卡进入、卡片浏览、末卡退出各有不同范围 | 不能把作品 DOM top 当作入场起点 |
| 指针 | 屏幕中央椭圆区域的追随残差拨动玻璃；玻璃回正与相机位置视差独立 | 移除首屏持续缓转和固定 ±8° 近似；停在边缘不能继续强拨动玻璃 |
| 图像 | 双层平滑、圆整中心吸引、sin/cos 弧线、固定曲率、位置/朝向/透明度共同变化 | 真实相邻入口组成前后层；不能只做一张平面横移 |
| 停滚 | 卡片视觉靠拢中心与文档 snap 是两层机制 | 停滚仍有追赶/吸附；新滚轮可打断；不得将静帧当完整节奏证据 |
| 标题 | 独立进入阈值触发字符动画，不跟着每个滚动帧简单变 opacity | 固定安全区，同步可见项/焦点，快速反向取消旧目标 |
| 明暗转场 | 透视矩阵向正交矩阵过渡，再用自下向上的软弧边合成亮场；曲率受进度差影响 | 分别验投影和 mask，连接实体白墙；不能全屏 opacity 一次变白 |
| 加载 | 几何施工线、轮廓描绘、黑幕淡出、径向 UV 弯曲揭幕 | 重新做阶段编排，不以单个 CSS 圆形 clip 代替 |
| 控件 | 导航扰码、Contact 双行翻字、More Works 下划线有不同机制 | 真实接通现有 data-scramble；没有依据添加磁吸和 hover 音效 |
| 手机 | 全屏淡入模糊菜单；布局高度/吸附/图形比例有独立规则 | 非桌面等比例压缩；保留原生触摸并补本站焦点与减少动画 |
| 切页 | GL 与 DOM 的退出/进入分层，首次 loader 不重播；popstate 取消待完成转场 | 用 Astro 生命周期适配其可见行为，不直接重建第二套路由 |

明确排除源码误读：Works 顶点里的滚速变形系数实际为零；另一个 WORKS 字带 mesh 默认隐藏且未发现启用路径；Service 多纹理定时轮播在当前单素材数据下不运行；定义了 `service` 旋转参数不代表实际 `service_0/1` 会使用它。不得为这些未运行分支增加假效果。

## 4. 原站距离与画面证据

桌面 H=900，原站有六张作品。下列 trigger 范围由**已测 DOM + 已核对源码**计算；没有冒充直接读取运行中 ScrollTrigger 对象。

| 通道 | 实际 DOM top / height | 推导 trigger start → end |
| --- | --- | --- |
| kv | 0 / 900 | -900 → 100 |
| works_intro | 1000 / 900 | 100 → 1000 |
| works_progress | 1900 / 5400 | 1000 → 7300 |
| works_snap | 同作品容器 | 1900 → 6400，中心每隔 900 |
| works_outro | 7300 / 1350 | 6400 → 7750 |
| mission_in | 8650 / 900 | 7750 → 8650 |
| service_in | 14140 / 900 | 11890 → 13690，明显早于 DOM 到顶 |

手机 H=844 时 works 容器为 5064px，而 mission_in 为约 590.8px、vision 为约 317.7px；这些差别是真实布局，不得套桌面的等长章节。

## 7. 第一片与后续顺序

当前第一片归 T03.02：**把序章到第一张入口做成相同输入、可连续对照的运动。**前置是将 The Wall 占位素材单独接成固定比较基线；不得同一批再改玻璃几何、灯光、字体或业务模块。

先建立正确触发区间与共享采样，再接首卡轨迹和 DOM 事件；第一片过关后扩到四张，随后指针/背景反馈、亮场与升墙、加载、导航菜单与切页依次单独核验。具体工程提示词和每片交付见开发任务单第 0 节。上述顺序是为了逐项验证，不表示后续动效可以省略。

### 同输入对照协议

1. 桌面两端同为 1440×900、DPR 1；加载完成后同一延时启动。指针固定同一位置，记录开始时间。源站作品数与本站不同，但首卡入场距离相同。
2. 标题引入五点为 100/325/550/775/1000px；首卡进入五点为 1000/1225/1450/1675/1900px。每点记录请求位置、实际位置与到位后 0/250/1000/2000ms 状态。
3. 首卡中点存在 round 阈值，补测 1449/1451px 并区分正反方向。源码推导的中点不是唯一静帧，不能给持续旋转的玻璃指定唯一 yaw。
4. 动态各做慢滚、单次快滚、跨中点立即反向；保存 deltaY、事件间隔、真实 scrollY、各进度、卡片 transform、标题活动项。以同进度及到位时间对照，不能仅比滚轮总量。
5. 第一张居中后点击真实 CTA；浏览器后退回当前段。键盘聚焦只能进入可见入口，过渡中的旧文字不得拦截点击或出现在顶栏上。
6. 手机先验证相同比例与菜单，再独立录真实 touch 输入；模拟窄屏截图不记为真机性能或触摸已验。减少动画、无脚本/无 WebGL 保留顺序静态入口。

通过要求包括阶段/轨迹正确、同输入追赶关系一致、正反可打断、标题与 CTA 安全且真实可用。后续原站与本站必须提供可并排的连续帧，不再只交五张漂亮终态。数值差异或体验偏差逐项登记，不用构建成功、零 console error 或“感觉差不多”代替设计验收。
