Someone 适合采用有留白的编辑式人物介绍，结合清楚的经历索引与真实的内容链接。首屏让访客认识“小石”，继续阅读能了解经历、能力和兴趣，也能直接找到联系入口。本文比较六个个人站，首选三个构图和组织参考：Dennis Snellenberg、Brittany Chiang、Anthony Fu；Paco Coursey、Steph Ango、Maggie Appleton 补充内容叙事。

## 项目依据与实际基线

- [SPEC 的 P02](../SPEC.md#p02p15-关于我和全局搜索)已规定姓名与简介、经历、能力、精选项目、联系与简历，采用可读的编辑式排版。
- [CONCEPT 命名基线](../CONCEPT.md#11-命名基线与歌词提案)把 Someone 定位为作品和履历之后的普通生活与局限；“小石”、Little Stone Still Here 和既有栏目命名沿用。歌词提案未获单独确认，本轮不把它变成首屏必需文案。
- [SYSTEM](../SYSTEM.md)规定黑灰、圆润克制、一个主要视觉重心、阅读时背景稳定；字号、正文宽度、颜色、间距与控件状态继续从该文件读取。
- 实际 [about.astro](../../../src/pages/about.astro)目前只有 Someone 标题、两段介绍占位和共用 JourneyPage。共用组件提供返回首页与“去学习总览”，尚无个人资料模型、经历、精选项目、联系或有效简历下载。这里是源码检查结果，不以文档规划代替实现。

## 建议的页面顺序

| 区域 | 要回答的问题 | 内容与操作建议 |
| --- | --- | --- |
| 人物首屏 | 这里是谁，为什么有这个网站？ | Someone 与中文功能说明、昵称“小石”、短介绍；真实照片作为可选视觉重心。联系方式有真实数据时，可在首屏给一个清楚的联系入口 |
| 个人叙述 | 是什么让这个人有辨识度？ | 两三个具体片段：如何学习、关注什么、音乐或影像偏好。只使用用户提供或已确认的内容，不把氛围词铺成自我评价 |
| 经历与能力 | 做过什么，能力从哪里来？ | 时间、事件／角色、一两句说明及相关作品或文章。能力附实际产出，优先普通列表；条目少时不画复杂时间轴，不做主观技能百分比 |
| 留下的东西 | 还能从哪里认识作者？ | 少量精选文章、项目、照片或音乐，链接到本站现有真实栏目；不在关于页重复一套完整作品库或播放器 |
| 联系 | 可以怎样交流？ | 明确标注邮箱与真实平台链接；邮箱可选择、可复制，同时保留直接邮件链接。留言可去 Outside the Wall，简历只在真实文件存在时出现 |

首屏可以借 Dennis 的尺度与留白；正文借 Anthony 的窄栏与内联链接；经历借 Brittany 的对齐层级。这是三个局部能力的组合建议，最终仍需要用本站中文、真实资料和黑灰规范验证。若资料较少，优先完成自然单栏；内容变长后才增加桌面页内索引。

## 交互与手机取舍

1. **入口能解释功能。** Someone 保留英文名，同时在页面内明确“关于我”，降低陌生访客的理解成本。
2. **正文先可读。** 普通纵向滚动，照片静态可见；入场反馈不延迟文字阅读。人物页不追加轮播、拖拽房间或持续漂浮背景。
3. **兴趣有真实去向。** 文章、照片、音乐和作品链接可直接访问；不把主要内容藏在头像 hover 或精细手势里。
4. **手机重排。** 页内侧栏并入单栏，经历日期置于条目正文前，联系入口保留文字名称；照片按内容裁切，不能用桌面比例压缩所有区块。
5. **返回有上下文。** 作品／文章详情返回后保留关于页阅读位置；从首页进入后的返回状态沿用现有首页返回机制。直达、刷新与浏览器后退都要纳入后续验证。
6. **减少动画与焦点。** 关键链接提供可见键盘焦点；动画不能阻挡导航，减少动画时核心信息仍可读。交互动画可关闭的依据见 [W3C SC 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)，该条为 AAA，不把它误写成 AA 等级。
7. **控件尺寸按 Web 核对。** 后续按本站 SYSTEM 检查触控面积与相邻间距；[WCAG 2.2 SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)的 AA 基线是 24×24 CSS px 或适用例外，不把原生平台的 pt／dp 单位套到网页，也不把段落内链接机械扩成大按钮。

## 复用来源与验证边界

本轮从项目 [REFERENCES](../REFERENCES.md)的既有 Paco／Maggie 研究与 `resource-awwwards` 入口出发，按任务提醒 [Awwwards 作品集目录](https://www.awwwards.com/websites/portfolio/)用于案例发现；质量判断以具体 About／个人介绍页面为依据，不按奖项或热度推断可用性。

这些站点均为构图或内容组织参考；未复制第三方源码、人物照片、字体、Logo 或艺术素材。图像仅为本机研究截图，不进入 public，也不是生产素材许可。真正实施仍优先沿用 Astro、现有布局、语义链接与 CSS，不为参考站的框架增加依赖。

主技能为 ui-ux-pro-max，定向检查深链、hover／触控替代、可见焦点、正文宽度及减少动画。Python 命令命中不可用的 Windows 应用别名，本轮改为只读检索本机 ux-guidelines.csv 的相关规则，没有生成第二套设计系统。

补查 [Guillaume Azadian About](https://guillaumeazadian.com/about)时，文本可读，但实际浏览器持续停留在 Hello 加载界面，故排除出视觉主候选。首次 Dennis 截图也是加载态，后续已取得完成态；Brittany 目录点击与若干包装 API 调用超时，未据此宣称导航通过。浏览器原图不证明完整转场、键盘、屏幕阅读器、减少动画、真机性能或大陆访问全部通过。

下一步如进入设计，只做一个最小切片：使用已确认的简介和可用个人照片，制作 Someone 首屏的桌面／手机静态样本，再逐项处理经历、联系与返回。当前任务到研究归档结束，应用实现与用户选型分别记录。
