# P01 · 光片改为连续扩散光晕

2026-10-10。P01 / R01、R12 / U03、U05、U14 / T03.01、T03.05。接收：首页开发 `01a11a75-b86e-7f00-84cc-3e3568943cfc`。

## 1. 用户依据和失败点

用户说“现在的光源方式不对怎么可能是两个光片，应该是光晕晕开”，附[近侧面截图](evidence/u03-p01-2026-10-10-39-design/user-light-sheets.png)。实际源码makeHalo对内外圈分别在`sideZ * face`（face ±1）生成二维扩展带，DoubleSide着色。侧视露出的两片是几何机制问题，37轮降低白芯和扩大衰减未解决；此前执行者复核不能作为用户已认可的依据。

## 2. 本片目标

保留38D最新形体和已放大的尺寸，仅替换光晕生成方式。视觉与参数唯一依据：[SYSTEM9.3.6](../SYSTEM.md#936-消除侧视光片的连续光晕39轮)。先完成38D最小保存，再开始39，不回滚用户在开发窗口的新形体纠正。

撤两张可见光带，使内外边缘、倒角、厚侧面共同产生连续柔光；60°/85°观察时只看到实体和散开的光，不见额外平面、灯柱、扇形或突然亮灭。相邻光自然融合，保留孔洞与黑色留白。

## 3. 复用与最小实现提示

- 当前Three0.186.1已提供`HorizontalBlurShader`、`VerticalBlurShader`（每方向9采样）及`FullScreenQuad`；源文件已在node_modules核对。优先复用官方二维模糊，以小范围适配发光mask、实体跟随及现有合成顺序。出处与候选比较见REFERENCES的P01-HALO-REF-04。
- 正反光带停止作为主场景可见几何。使用原实体几何的独立发光mask，随原mesh world matrix，保留遮挡/可见面与侧面连续受光。低分辨率mask与两次模糊可按手机/桌面控制；需要更宽扩散时复用相同shader和降采样策略，避免稀疏大步采样形成九重影。
- 已有BlackFlowLayer在priority1主导场景和前景卡片合成，GlassOptics在-.5采背景，Drei普通材质有自己的捕获。先核对当前顺序；接入同一渲染链，恢复render target、camera layers、autoClear、toneMapping等状态。最终光不进入玻璃背景捕获，不覆盖前景卡片与DOM内容。不安装第二个后处理框架，不用全站Bloom让曲线/文字一起发光。
- 官方UnrealBloomPass可作多尺度模糊参考，但本片不直接加整套EffectComposer覆盖已有compositor；没有采用完整Bloom类就不要在报告中声称用了它。
- 只新增本片必要资源，离开/零强度时跳过无效渲染，resize和dispose完整。普通模式使用同样的连续光晕机制；失败时保留可读实体，不能恢复用户否定的两片光。

## 4. 一批验收

1. 固定光/背景和姿态：桌面0°、60°、85°；390 CSS px正面、85°。优先沿用既有采样方式，新增角度即可，不新建查看器。保留新旧近侧面图。
2. 侧视不能看到几何光片/光柱、端点硬切或离散重影；光域贴边连续，内孔可读。实际滚动/指针短转动確認没有角度突变。
3. 一次手机首卡收光与反向恢复；普通/增强模式各观察一次，关注新光晕反馈及位置，而非重测所有输入功能。
4. 新增GPU资源需一次短资源窗口和resize/离开清理核对；记录增加的targets/passes及实际设置，模拟器不当真机性能。一次check/build。
5. 设计一批复核，若有具体缺陷集中修正一次。实际图通过再最小源码提交和短报告；不将加载34或完整展开记作已完成。
