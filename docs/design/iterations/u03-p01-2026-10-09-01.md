## 1. 推荐与现成方案缺口

建议复用项目已安装 **Three 0.186.1 的官方 GPUComputationRenderer**，在现有 R3F Canvas 中承载流体计算与 FBO；按 [SYSTEM 9.2.4](../SYSTEM.md#924-亮场与白墙) 补必要的输入、求解 shader 和黑场采样适配。它是成熟计算工具，不是现成 ALCHE 流体效果，不能把导入工具记成流体完成。

按 [六资源站规则](../REFERENCES.md#六个设计资源站与提醒规则)，本轮优先查看了 [React Bits Liquid Ether 可体验页](https://reactbits.dev/backgrounds/liquid-ether)及官方代码。它可以作为独立彩色流体背景；拆入本站需要替换输入、求解和输出三段，原样安装又会新增 renderer/Canvas/RAF。因此本轮不推荐复制该组件；保留为已查候选，无新增依赖。

## 2. Liquid Ether 与已有 ALCHE 证据的实际差别

ALCHE 基准来自已存 [source-fluid-report](evidence/alche-motion-2026-10-08/source-fluid-report.txt) 与现行 SYSTEM；本轮没有重新运行原站，也没有把报告列出的片段索引当作已重新核对全部原始 shader。下表用于说明复用成本，正式参数仍只由 SYSTEM 维护。

| 环节 | Liquid Ether 固定版本 | ALCHE 目标与适配判断 |
| --- | --- | --- |
| 宿主 | 源码 144 行创建 renderer，1070 行自建 RAF；销毁会 forceContextLoss | 必须移除整个 Common/WebGLManager 宿主，注入现有 gl 与时钟，不能保留其销毁逻辑 |
| 输入 | 307 行取前后帧坐标差，固定 cursorSize，默认自动演示 | 目标为两级追随残差、非线性累加与动态半径；输入需要替换，不能沿用玻璃旋转用的残差就省略第二级 |
| 场与预算 | 834–865 行分配七个 FBO，默认半视口分辨率、32 次压力迭代 | 目标固定长边、打包场、四次压力迭代；大小可配，但数据组织仍需改造 |
| 求解 | 951–970 行先平流，再外力、可选粘性、散度、压力、投影；平流带 dt/BFECC，无 curl/涡度 pass | 目标九 pass 顺序及逐帧消散不同；关闭选项和改迭代次数不足以等效，需要重排并改写大部分算式 |
| 输出 | 464–481 行按速度长度查 palette，再输出颜色/透明度 | 目标是扭曲既有场景采样并作规范内亮度变化；输出段必须替换，不能新增一层彩色液体背景 |

可留下的主要是通用全屏 pass 和 FBO 管理。这部分已有官方工具覆盖，因此继续拆约 1,258 行组件不会形成更小的复用范围。

## 3. 推荐工具的能力与最小适配

GPUComputationRenderer 构造函数接收既有 renderer；官方文档明确支持 `createShaderMaterial`、`createRenderTarget`、`doRenderTarget` 串接纹理计算。本站安装包源码 113、394、457 行已核对：RGBA 浮点目标、显式纹理类型、完整屏幕 pass，以及正常返回时恢复原 render target。它本身不创建 Canvas 或 RAF。

注意该工具 260–289 行的 `compute()` 会让变量读取同一旧缓冲，不能把九个顺序步骤注册为九个变量后只调用一次。建议用官方 `doRenderTarget` 配合显式 ping-pong 顺序；创建目标时指定 SYSTEM 要求的 LinearFilter，不能沿用工具默认 NearestFilter。自行创建的材质/目标分别释放。

最小应用适配范围为：

1. 一个无 DOM 的流体实例：接收已记录的原始 NDC，管理输入追随器、打包场与临时目标；实现六类必要 shader（压力 shader 运行四次），暴露 `flowTexture`、更新、重置、resize、dispose。算法依据 SYSTEM 独立实现，不复制 ALCHE 专有代码。
2. 一个 R3F 接线层：沿用 [WorksMotionDriver](../../../src/components/home/WorksMotionDriver.tsx) 的唯一帧循环，先读输入并求解，再统一更新输入追随器；复用第 27/29 轮最终的初始化 revision 和生命周期。恢复时处理零场/零注入初态，暂停或隐藏时不补算离开期间的帧。
3. 一个黑场采样 pass：沿用 [GlassOptics](../../../src/components/home/GlassOptics.tsx) 的折射快照，再将既有黑场内容与玻璃统一渲染到主黑场 FBO、按 flow 作屏幕空间采样；[WorksScene](../../../src/components/home/WorksScene.tsx) 已有 layer 1，可在其后清晰叠加，DOM 留在独立语义层。此方案能够覆盖整个主黑场的连续采样关系，单独修改砖纹/文字材质 UV 不能作为同等实现验收。flow 不直接作为玻璃 normal map。

需集中保存/恢复 render target、camera layers、autoClear 等 renderer 状态，保留第 28 轮线性色彩/显示转换边界。若采用正优先级接管最终渲染，按 [R3F 官方 useFrame 规则](https://r3f.docs.pmnd.rs/api/hooks#taking-over-the-render-loop)关闭默认自动绘制，并在同一回调完成必要绘制，避免双绘制；不要另开 RAF。

这是本片最小合理合成边界：现有玻璃背景捕获 → 主黑场 FBO → flow 屏幕合成 → 清晰 layer 1 四卡；已有 DOM 独立覆盖。resize 同时校正计算场比例、颜色目标和分辨率 uniform；dispose 只释放本片拥有的目标/材质，保留共享 gl。进入墙段或关闭此层时 flow 采样与亮度贡献保持中性，墙继续使用原有输出。

### 3.1 第30轮颜色对照后的捕获修正

2026-10-09初批中，新主场HalfFloat FBO在零flow下仍未通过0/550/1350三个位置的29构建对照。普通离屏目标在工作色域混合，原默认屏幕路径在显示编码后混合；半透明文字和抗锯齿边缘可能因先后顺序改变。此解释还需结合实际差异图确认，不能只靠toneMapped=false宣布颜色保持。

设计侧允许并优先验证Three官方[copyFramebufferToTexture](https://threejs.org/docs/pages/WebGLRenderer.html#copyFramebufferToTexture)：先按原路径把layer0渲染到默认framebuffer，再复制完整黑场画面到专用FramebufferTexture，随后统一warp、最后叠加layer1。仍是同一画面的整体屏幕采样，不退回逐个砖纹/标题UV改动。显示编码的复制纹理须在最终pass显式且仅一次解码、线性增亮和显示编码；玻璃内部折射快照继续保持原线性路径。

这替代前述“必须通过新主场FBO”的具体技术选择，保留整个黑场→流体→清晰前景的视觉边界和所有原参数。现成GPU复制能减少对既有材质的改造；代价是一次整屏复制和屏幕位深限制。需要同尺寸/DPR、零flow仍经完整复制合成、半透明卡/标题、resize及销毁证据；真机性能仍另验，低档/减少动画/无hover继续停用。不得伪装isXRRenderTarget或修改引擎私有分支绕过色域规则。

同轮曾短暂验证集中在独立helper的 `onBeforeCompile` 主捕获编码适配；最终实现已选择上述官方GPU复制，不再维护两套捕获路径，也不改既有材质文件。设计原生复核读取的主包为 `HomeJourney.CHZQwtNe.js`，实际流体扰动可见；颜色与分层结论以30轮固定状态对照为准。

## 4. 下一工程片的用户可体验边界

唯一主要变量是 **flow**：顶部砖纹/细光线及 works_intro 的背景字会随指针局部扰动，停下后尾迹逐渐消散。内部先验求解场与输入，再接同一黑场采样；两个检查点属于同一交付，只有调试流场不能记作用户功能完成。

当轮首批可辨认载体是 [SceneBackdrop](../../../src/components/home/SceneBackdrop.tsx) 的 kv 砖纹/光线，以及当时的`WorksIntroTitle`序章背景字（该组件后按用户要求在[35A](u03-p01-2026-10-10-35a-implementation.md)移除）。当轮1440×900的S=550可用背景字核对，其他视口由SYSTEM进度换算。SceneBackdrop在旧progress的.6→1淡出，works停驻时接近纯黑；纯黑区没有可辨纹理，不能拿它证明采样位移可见。此段保留当轮验证语境，不要求恢复已取消的背景字。

四卡、DOM 文案、配色素材、镜头、旋转和墙动作保持本片基线。全局第二次 scene composite 采样、亮墙的反向 warp、展开窗口与墙场景接续后续独立实施。**黑场第一片通过不等于全部场景流体覆盖或完整叠层转场通过。**

## 5. 五项判别验收

1. **真实单时钟与求解：**记录实际 Canvas/renderer 数量、每 RAF 求解轮次、场尺寸、九 pass 顺序与 Float/过滤状态；零输入场稳定、数值无 NaN。诊断只在验收入口出现。
2. **可见输入与消散：**相同路径快移/慢移各一次，在 kv 砖纹/光线和 intro 背景字记录原始输入、平滑位置/残差、buffer 及停下 0/250/1000/2000ms；验证速度影响强度和半径，停住后没有自动演示或固定光圈。
3. **分层与颜色：**固定时钟/姿态比较 flow 开/关；背景有位移，四卡与 DOM 边缘、CTA 命中不被 warp。零场时原色彩路径保持，避免新增 ACES 或 sRGB 二次变换；调试场不能作为最终画面证据。
4. **恢复与销毁：**暂停、隐藏、继续及一次栏目返回，核对新 epoch 无陈旧注入力爆发；连续重入无新增 Canvas、监听或持续增长的 render target，关闭层仍保持首页可读可点。
5. **输入能力与降级：**区分窄桌面鼠标与真实 coarse/no-hover 设备，不能直接复用当前把窄屏也判 mobile 的布尔值。减少动画、低档、浮点目标不可用时关闭该层；触摸保持原生滚动。记录实机能力与帧耗时，软件 GPU 截图不能证明真机性能。
