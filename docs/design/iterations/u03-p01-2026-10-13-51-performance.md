# P01 · 白光样本卡顿修正

2026-10-13。P01 / R12 / U03、U14 / T03.05、T26.02、T27.01。用户问“你这个是用什么做的怎么这么卡”，按纠正继续诊断与修复；物理白光后续门槛仍见[51工程记录](u03-p01-2026-10-12-51-implementation.md)。此片只处理4339独立样本的运行开销，不混入光谱/首页接入或音乐工作。

## 使用的实现与实际瓶颈

4339的`/white/`是独立HTML加Three0.186.1/WebGL2；CPU使用实际几何求解器追踪有限源，GPU用局部光子束单散射估计和接收面着色器显示。现成three-gpu-pathtracer只在根路径失败首样使用，当前白光页并未采用它的完整路径追踪循环。主站Astro/React未接入本样本。

实际IAB报告ANGLE Intel Graphics Direct3D11。添加可见计时后，同正面128源样本/640段/128受光命中，两次静止GPU均值173.239、174.715ms，JS提交约.597/.398ms，CPU源路径重建平均10.983ms，帧间距约176–177ms。主要瓶颈在空气积分着色器；它每个片元做16次积分，每次都对505个界面平面作玻璃遮罩。源采样完成后仍持续draw，87→215帧而epoch保持6；原“暂停源采样”也没有停止这些draw。用户此前接受画质优先不等于接受无变化时持续占用GPU。

## 修复

1. **按需调度：**空间源采样达到128后不再预约RAF。控件和尺寸变化按需恢复，连续输入合并为一个待执行帧；隐藏取消待执行帧，显示仅恢复未完成工作，pagehide取消调度并释放计时查询/原资源。
2. **同一几何的射线区间：**实际几何包围盒先快速剔除；可能穿过玻璃时，对同一505个凸界面求一次观察射线区间，16个积分点改为判断是否落在区间内。没有简化几何或把玻璃改成代理三角形。
3. **同一积分权重：**Gaussian和Beer组合的指数在射线参数上为二次式，用递推计算同一16个中点权重，指数调用由每点重复变为三次，相函数移到循环外。128源样本、16积分点、源角度/功率、Fresnel、光宽及真实路径均保持。
4. **计时分开报告：**CPU光路、JS提交与GPU完成时间分别保存；页面显示最近GPU帧。GPU计时由可用的异步timer query读回，不用JS提交耗时冒称GPU速度。性能文字移出布局流，避免它自身引发滚动条和画布重排。

计时API依据：[MDN EXT_disjoint_timer_query](https://developer.mozilla.org/en-US/docs/Web/API/EXT_disjoint_timer_query)区分WebGL2扩展及纳秒结果；[requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)为单次预约，连续工作须显式重约。没有额外主站依赖。
