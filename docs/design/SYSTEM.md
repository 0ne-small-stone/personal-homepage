## 1. 总原则

**整体圆润、克制；氛围迷幻、辽阔、温柔；功能清楚，动作有因。** 2026-10-07 用户明确将“圆润、克制”用于整体设计，覆盖场景、平面、控件及运动。黑色首页与白色留痕墙属于同一空间。空间效果集中在首页与靠近过程；阅读时保持背景稳定。页面与功能归属见[页面规格](SPEC.md)，完整概念见[概念施工说明](CONCEPT.md)，迭代与验收见[工作流](PLAN.md)。

同一职责使用同一变量。实现时按“原始值 → 语义用途 → 组件”组织，例如 `--ink-900 → --color-text → --button-text`。组件读取语义变量；页面换深浅背景时替换语义映射，不逐个写新的颜色。

### 1.1 圆润与克制的落地方式

用户已确定整体风格，以下是供样本验证的施工解读，具体参数尚未获审美验收。

| 层次 | 圆润的表现 | 克制的表现 |
| --- | --- | --- |
| 墙体与棱镜 | 边缘轻微倒角、转折柔和，保留长方体和三角截面的清楚轮廓 | 块面完整，纹理少；形体尺度与受光承担识别，控制边缘高光强度 |
| 光影与颜色 | 光束边缘柔和，明暗连续，接触阴影轻 | 既有中性色为主，色散集中在必要落点；正文和控件对比仍按第 2 节验收 |
| 构图 | 内容周围留有呼吸空间，疏密过渡自然 | 一个主要视觉重心，清楚的分组与留白；优先用位置和间距组织内容 |
| 排版 | 字形舒展、字重平衡、中文行距稳定 | 少字体、少字重层级；英文名称和配句服从识别与阅读，不做装饰性堆叠 |
| 控件与图标 | 适度圆角、圆端线性图标、稳定的点击区域 | 操作层级明确，弱化无用途边框；不统一加厚阴影、磁吸或悬浮变形 |
| 动画 | 变化连续，起止柔和，可自然中断和反向 | 同时只有一个主要运动焦点；反馈及时，普通控件不增加回弹或等待，阅读时安静 |

圆角按对象比例分级。墙砖保持平整面和规整接缝，棱镜保持折射方向可读；原始照片、截图与正文的可读信息完整保留。现成组件按其主题能力适配，控件名称、焦点和状态反馈持续清楚。

### 1.2 Logo 已确认外观与历史探索

最新第七轮按用户新附件精修独立手写字标。字标为小写两行 `little stone` / `still here`，参照《迷墙》手写笔触，固定换行，不由响应式排版任意断句；站点元信息中的标准站名仍按 CONCEPT。长笔画、斜向横笔和手写粗细变化保留，统一字形辨识、字距与两行重心。第六轮双侧脸组合稿保留历史。

当前为用户已确认的[独立字标精修稿](iterations/samples/u03-p01-2026-10-08-07/lssh-wordmark-black.png)及[白字透明 PNG](iterations/samples/u03-p01-2026-10-08-07/lssh-wordmark-white-transparent.png)，由内置 AI 编辑生成，均为 1536×1024 位图。透明版已在黑底与灰底、600px 与 300px 画布宽度下实看；缩放保持原比例，替代文字用完整标准站名。后续品牌手册的安全区与最小显示尺寸基线见 1.3；尚无正式矢量母版或 favicon。以下较早各轮只作历史说明。

2026-10-08 前两轮均被用户否定。最新要求是极简、有辨识度和寓意，仅做五版主 Logo。第三轮去掉膨胀扭曲的有机曲线，使用少量几何形体、清楚轮廓和宽裕负形；统一黑底单色意图。源稿与提示词见[第三轮文件](iterations/samples/u03-p01-2026-10-08-03/generation.json)。当前为 PNG 候选，生成图存在轻微色调变化，尚非标准单色矢量母版，未验证反白和 favicon。网站名称与简称仍以 CONCEPT 为准。

第一轮的 Instrument Sans 字标组合保留为历史探索；第二轮只生成标志形体，评审页的系统字体和 Georgia 仅为说明排版，不是正式品牌字体。中文说明置于图形外，不新增品牌强调色，不改变学习区字族。选定方向后再校准矢量曲线、字标、最小尺寸、安全距离和反白规则；当前不为五个候选分别建立永久规范。

## 2. 颜色与明暗

2026-10-07 用户指定以《月之暗面》封面背景的纯黑作为主题底色，以 Codex 的灰色观感作为次级颜色。**暗景底色固定为 `#000000`**，替代此前带冷色倾向的近黑；次级表面与通用交互强调收敛为中性灰。Codex 灰色的具体区域与色值尚未取样，下表深灰属于本站施工候选，不作为 Codex 官方色值或用户已确认的精确灰值。

| 语义变量 | 暗景 | 浅面 | 用途 |
| --- | --- | --- | --- |
| `--color-bg` | `#000000` | `#E8E4DC` | 页面底色；浅面也是白墙基色 |
| `--color-surface` | `#1F1F1F` | `#F2EFE8` | 次级面板、菜单、输入框等稳定内容/控件底面；暗景灰值待观感校准 |
| `--color-surface-active` | `#2A2A2A` | `#E8E4DC` | 当前交互项或悬停底面，配合文字、图标或边界反馈 |
| `--color-text` | `#EDEDED` | `#272A2C` | 正文、标题、主控件 |
| `--color-muted` | `#A1A1A1` | `#62645D` | 辅助说明与元信息 |
| `--color-accent` | `#D4D4D4` | `#444444` | 中性灰强调，用于链接、当前项、焦点；保留文字或边界区别 |
| `--color-border` | `#777777` | `#72746E` | 必须辨认的控件边界，按不透明色使用 |
| `--color-divider` | `#242424` | 未指定 | P03 行分隔与辅助结构线；不能替代焦点、选中边界或文字；浅面使用前另验 |
| `--color-success` | `#A9C3AE` | `#3F6547` | 真实成功状态，配合文字 |
| `--color-error` | `#EDB4AC` | `#9A3D35` | 错误与恢复提示，配合文字 |

- 黑色提供主要空域，灰色仅在需要内容分层或操作反馈的位置出现；背景不铺满灰色卡片或冷色渐变。低受光墙轮廓与局部光可以叠加在纯黑底上，保留大片未被照亮的黑色区域。
- 细分隔线和装饰砖缝可以更弱；关键控件不能只依靠低透明度边线辨认。灰色底面的亮度差不能独自承担焦点或选中识别。
- 光的色散是棱镜的局部光学表现，与通用控件强调色分开。首轮用中性光验证方向与层次，后续单独验证少量色散；各栏目沿用黑灰界面，作品与照片保留原色，成功/错误色仅用于真实状态。
- 暗景/浅面是表面配色。首页与白墙按场景选择；阅读配色可独立调整，不改变场景进度。
- 普通文字目标至少 4.5:1，大号文字按定义至少 3:1；本站关键控件边界和焦点设计目标至少 3:1。[W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

**已做的数值检查：**2026-10-07 按 sRGB 相对亮度公式重新核算表内不透明前景色与背景、表面、交互表面。文字及状态色最小对比度：暗景 5.56:1、浅面 4.73:1；关键边界最小值：暗景 3.21:1、浅面 3.73:1。替代此前旧配色的检查结果。此结果只验证色值组合；图片、透明度、辉光和蒙版参与后的实际画面需另测。边界色不用于普通文字。

## 3. 字体与排版

2026-10-07 用户更新：学习区（资料、博客、数字花园）的标题、正文、目录、控件和辅助说明统一采用苹方优先的 `--font-reading`：`"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", "Noto Sans SC", system-ui, sans-serif`。不分发苹方字体文件；无苹方设备使用本机回退，实际渲染字族须读回。此规则覆盖下表对学习区的通用字体建议；本轮 T09.03 仅接入阅读字体栈，其他视觉参数以最新设计聊天的独立样本验收为准。

| 用途 | 初始规范 |
| --- | --- |
| 学习区常规文字 | `--font-reading: "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", "Noto Sans SC", system-ui, sans-serif`；苹方始终放在字体栈首位 |
| 其他页面正文与控件 | 系统无衬线：`system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif` |
| 学习区字重 | 正文 400，标签与控件 500，标题与强调 600；层级由字号、字重与间距形成，具体效果待样本验证 |
| 其他区域展示性标题 | 思源宋体保留为候选，仅用于少量展示标题；未接入时用 `"Songti SC", SimSun, serif` 回退。学习区标题统一使用 `--font-reading` |
| 代码与数字刻度 | `ui-monospace, Consolas, monospace`；时间与进度用等宽数字 |
| 正文 | 手机 16px、桌面 18px，行高 1.8，字重 400 |
| 控件标签 | 14–16px，行高 1.5，字重 500；手机表单输入文字至少 16px |
| 辅助信息 | 13–14px，行高 1.5；主要操作和错误说明不缩成小字 |
| 页面标题 | 手机 32px、桌面 48px；首页短标题可到 64px，行高 1.2–1.3 |
| 二/三级标题 | 24px / 20px，行高 1.4；清楚区分层级 |
| 正文宽度 | 约 36em，中文每行约 28–40 字；容器不得超过可用宽度 |

字号实现使用 rem 与响应式约束，尊重浏览器文字缩放。中文自然换行，长 URL/代码单独处理。代码保留等宽字族，数学公式保留排版组件所需字体；PDF、图片内文字与外部网站保持原文件或来源排版，网页中的资料标题、简介、目录和操作区遵守上述苹方规则。

苹方按本机已安装字体调用。[Apple 系统字体清单](https://developer.apple.com/fonts/system-fonts/)列有 PingFang SC 的 Regular、Medium 和 Semibold 等字重；当前项目没有可分发的苹方网页字体资源，本轮不下载、转换或随站分发字体文件。未安装苹方的设备按同一字体栈回退，实际使用字族与换行须在验收时记录，不能仅凭 CSS 声明标记为苹方显示通过。

其他候选字体若需以网页字体交付，应先登记具体文件、版本与许可，再按实际字形和字重优化；核心内容在字体加载前即可读，避免一次加载整套多字重中文字体。

## 4. 布局、边界与图标

- 间距阶梯：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96px`；实现换算为 rem。组件内部优先 8–16，分组 24–32，页面章节 48–96。
- 页面侧距初值：手机 16、平板 24、桌面 40；内容容器最大 1200px，阅读正文使用独立窄栏。
- 宽度断点初值：768、1024px。根据内容重排，不能只把桌面场景等比例缩小。手机四入口按学习、展示、网站、电台顺序重排。
- 圆角采用下表初始变量，在实际大小下验证；替代此前偏硬的统一圆角基线。胶囊只用于确有需要的紧凑状态，分组优先靠留白组织。
- 普通分隔线 1px；焦点外框 2px、外偏移 3px。阴影只帮助区分展开层与背景，首轮不为每个卡片加阴影。
- 图标优先沿用已有组件；本站自有图标统一采用清单中的 Lucide 线性风格，常用 18/20/24px，描边统一。装饰图标不重复朗读，独立图标按钮必须有名称。
- 合成顺序：场景背景 → 内容 → 固定导航 → 弹层遮罩与弹层 → 状态提示。装饰层不接收指针事件；全屏弹层覆盖导航并管理焦点。

| 圆角变量 | 初始值 | 适用范围 |
| --- | --- | --- |
| `--radius-compact` | 4px | 小标签等紧凑元素 |
| `--radius-media` | 8px | 媒体预览外框；原图放大与正文内容按实际比例完整展示 |
| `--radius-control` | 10px | 本站自有按钮、输入、筛选控件 |
| `--radius-panel` | 16px | 展开面板、菜单和对话框外层 |

实现时转为 rem。以上是二维控件候选值；三维墙砖和棱镜的倒角按形体比例与观察距离验证，不直接套用 CSS 像素圆角。最终数值以本轮实际样本记录回写。

## 5. 控件与交互

### P13 首片双模式布局（2026-10-11）

复用第 2–5 节黑灰语义色、苹方正文、IBM Plex Sans 展示标题及现有 HomeLayout。正文容器沿用最大 1200px，侧距手机16/桌面40px；Echoes标题手机48/桌面96px，以页面当前曲目和目录形成一个主层级。模式用44px以上的分段按钮，选中有文字/底面与 `aria-pressed`；目录单曲行、专辑入口最少44px，8px媒体圆角，10px控件圆角，16px展开面板。桌面当前曲目/目录为约1:2双列，768px以下纵向重排，目录计数和下载入口纵向排列。没有音源时当前曲目区域呈真实待连接说明，播放控件不可用；错误和刷新结果在控件附近以正文反馈。网易云使用原生330×450px界面；窄于330px的可用容器按宽度等比缩放全部iframe，并同步容器高度，保留完整控件，外围不伪造播放进度。首片执行者读图及实际检查通过，用户审美确认另记。

本站独立按钮有效点击区以 **44×44 CSS px** 为设计目标，相邻独立目标优先保留 8px 间距；这是本站目标，高于 WCAG 2.2 AA 的 24×24 CSS px 基础要求（标准另有间距等例外）。正文链接保持可读的自然排版。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

| 状态/类型 | 统一规则 |
| --- | --- |
| 默认 | 目的地用链接，改变状态用按钮；文案说明动作与对象 |
| 主要动作 | `color-text` 作按钮底、`color-bg` 作字色；同一区域保持明确重点 |
| 次要动作 | 稳定底面、可辨边界与文字；工具链接可用文字和下划线 |
| 悬停 | 局部颜色/边界增强，点击区不变；必要说明同时支持焦点或点击 |
| 焦点 | 使用 accent 外框；不被裁切或遮挡；发光不能替代轮廓 |
| 按下 | 立即反馈明暗；不移动布局、不让小按钮追着鼠标走 |

### 9.2 运动与滚动

#### 9.2.2 卡片、背景与文字

原站 `L(target,m)`：首次直接取 target；以后每帧 `current+=(target-current)*min(1,dt*10*m)`，并保留更新前的 `target-current` 作为追随残差。它不是“动画持续 m 秒”。每帧调用顺序与采样时刻必须固定。

令 `p=L(works_progress,1)`、`o=(N+1)*p`、`u=L(round(o)+.4*(o-round(o)),.5)`；第 i 张卡 `d=i+1-u`：

| 属性 | 参考坐标基准 |
| --- | --- |
| 位置 | `x=11*sin(d)`，`y=-d`，`z=5*cos(d)-6` |
| 朝向 | `rotationY=.6*d` 弧度 |
| 比例 | `.9+.1*spWeight+.2*(1-min(1,abs(d)))` |
| 透明度 | `(1-smoothstep(.8,2.5,abs(d)))*min(1,2*u)*min(1,2*(N+1-u))`；`alpha<=.01` 隐藏 |
| 固定曲面 | 原平面局部 `z=.2*z+1.5*cos(x*PI/16)-1`；不是随滚速任意波动 |

背景图片另读 `b=L(works_progress,.7)*(N+1)`，前后两张作横向软擦除，边缘宽 `.03` UV；前景不随之透明混合。具体公式在来源报告，背景保留本站低亮度黑灰空间；专辑色只在局部内容和折射中出现。背景标题可见度为 `smoothstep(.1,.3,a)*smoothstep(1,.9,a)`，`a=L(works_intro,.3)`。原站另一个隐藏的字带 mesh 不作为必须实现的效果。

**本站序章身份层的交接（21 轮修正）：**批准字标、短句与“向下探索”共用一个可逆退出进度 `q=clamp01(S/G)`，opacity=`1-smoothstep(0,1,q)`；在 `S>=G` 时完全隐藏并设 inert/aria-hidden，在 `S<G` 时恢复可见及语义可达性。该区间为 LSSH 额外身份层的设计适配，不冒称原站参数。背景大标题继续使用原站 works_intro 进度；不得把身份文案的退场拖到整个 works_intro 结束，否则两层文字相撞。隐藏阈值处若焦点仍在身份层内，仅将焦点移至可见的顶栏 LSSH 首页链接，使用 preventScroll；不主动抢走其他区域焦点。快速反向按实际 S 恢复，不排队播放退场。只应用于增强场景，普通浏览、减少动画与无 JS 保留正常文档内容；图形失败或离页销毁时清理隐藏状态。

标题事件与卡片的圆整中心分别计算：进入容器 opacity `.3s power2.out`，字从 `y=10px,opacity=0` 到 `0,1`，`.7s power4.out`、stagger `.01s`；说明延迟 `.3s` 再 `.5s power2.out`。离开字到 `y=-10px,opacity=0`，`.4s power2.in`、stagger `.001s`；说明 `.3s`，容器 `.5s power2.inOut`。快速反向时取消旧目标、从当前状态接续，不能让上一标题回来压住下一标题。CTA 的点击与焦点只属于当前可见项；过渡视觉副本不参与命中。

#### 9.2.3 指针、玻璃与相机

**居中基准：**kv、works_intro、works 浏览期的玻璃锚点是视口 `(50%W,50%H)`；不再读取旧版每章左右偏移位置。中性输入、基准正面姿态、相机视差归零时，以实际轮廓包围框的中心校准几何局部偏移和父组位置；水平/垂直误差各不超过视口相应尺寸的 2% 作为首轮验收容差（本站标准，不是原站测量值）。模型原点、三角形面积重心和轮廓中心不是同一对象，不能只把 mesh.x=0 就宣布完成。

正常指针视差、玻璃旋转会改变瞬时投影轮廓，不每帧移动物体抵消这些动作。验收同时保存基准正面、静置和移动帧，并记录锚点投影；桌面和手机均保持中心构图，必要时调整尺度及 DOM 安全区。只有 portal_prepare/expand 明确转侧时允许形体扩展离开这个局部边界；原站 A 模型的 y 补偿不能直接照搬给本站三角环。

鼠标 NDC 为 `(2*x/W-1,1-2*y/H)`。旋转驱动力按中心权重 `m=.01*max(0,1-1.5*length(NDC))*hoverMultiplier` 计算；作用半径 `2/3` NDC，椭圆半轴约 `W/3,H/3`。`vX/vY` 是 `L(pointer,1)` 的追随残差，不是 px/s。

| 状态 | worksRotate 目标 | 基础 Y 角速度 | 回正力 | 滚速系数 | hoverMultiplier |
| --- | --- | --- | --- | --- | --- |
| kv | 0 | 0 | 2 | 0 | 1 |
| works_intro | 1 | .5rad/s | .4 | .001 | .2 |
| works | 1 | .5rad/s | .1 | .001 | .2 |
| 退出与墙 | 0 | 0 | 2 | 0 | 0 |

`worksRotate` 用原站 `sigmoid(strength=6)` 在 1s 内切换。其精确归一化定义为 `f(t)=1/(1+exp(-12*(t-.5)))`，`E(t)=(f(t)-f(0))/(f(1)-f(0))`；原实现指数是 `-6*(2*t-1)`，不能误写成 `-6*(t-.5)`。在 t=.25/.5/.75 时 E≈.04517666/.5/.95482334，源码短摘录、哈希与偏差见 [21 轮精度证据](iterations/evidence/u03-p01-2026-10-08-21/precision-review.json)。这修正此前“k=6”简写的歧义，不代表当前 CameraRig 已修。29轮原始调用链复核修正顺序：GL先调用hover，按本帧Animator推进前的 `wBefore` 注入 `x-=vY*m*(1-.7*wBefore)`、`y+=vX*m`；随后MainLogo.update推进worksRotate，再将Euler乘 `1-dt`、z=0，构造鼠标四元数并前乘到物体。旧“先衰减再注入”的文字已撤销；它会改变每帧响应，不能仅记为允许偏差。基础 Y 增量为 `-dt*baseSpeed*w - L(clamp(Lenis.velocity,-30,30),.5)*scrollFactor`，第二项在原站没有再次乘 dt；最后按 `dt*returnForce*(1-.8*w)` slerp 回单位四元数。原站 GL dt 上限 `1/30s`；60Hz 样本先验证同输入响应，其他帧率的时间归一化修正单列对照，不能悄悄改变手感。

**29轮worksRotate时基确证：**名义1s是Animator累积封顶GL deltaTime到1，不是独立墙钟计时；持续低于30fps时实际秒数会拉长。玻璃控制与原站对照应同时记录GL累计时间和墙钟，软件GPU低帧不能直接作为曲线偏差证据。[原始调用链短证据](iterations/evidence/u03-p01-2026-10-09-29-timing.json)已固定到同一源包哈希；本次只确证worksRotate，不据此宣布其他通道时基均已复核。

相机基准 `(0,0,10)`，`baseFov=35+18/aspect`；kvZoom 初值 1，离开 kv 后按上述 1s 曲线到 0：z=`10-.5*kvZoom`，FOV=`baseFov-4*kvZoom`，始终看向原点。指针相机目标偏移为 `.5*NDC*(1-L(works_outro,.5))`，按 `min(3*dt,1)` 追随。鼠标停止在一处时相机保持偏移；不能把它与玻璃回正混为一事。

**旋转接入的生命周期约束（下一施工片）：**首次有效指针输入直接初始化追随器，不制造启动残差；离开窗口不得用强制归零产生额外反向拨动。恢复场景时消费现有统一初始化版本，玻璃取中性四元数、worksRotate直接置为该阶段目标，清空临时Euler与旧输入/滚速残差；普通阶段切换不执行此恢复重置，intro→works的相同目标不重复起播。暂停时保留姿态，继续时对齐最新指针并清除积累输入；减少动画继续静态后备。无鼠标的手机关闭hover驱动，仍保留works基础旋转和真实滚动响应。这些为本站生命周期适配，需实际验收。相同scrollY不保证相同yaw，对照还须记录停留时间及输入历史。

退场投影按 `L(works_outro,1)` 从透视矩阵过渡到正交矩阵：横屏短边 ±4、长边按 aspect 扩展，竖屏短边 ±4、竖边 ±4/aspect。先验证同构图连续性，不能以单纯推近相机替代。玻璃位置的手机适配与现有 LSSH 几何尺度单列校准，不照抄原站模型嵌套缩放。

#### 9.2.4 亮场与白墙

亮场目标为 `L(wall_reveal,1.5)`；每帧差值 `M=target-a`，`v+=(M-v)*.5`，`a+=M*.5`。mask 的 `range=1/resolutionY+abs(v)*.2`，`curve=-cos((uv.x-.5)*PI)*v*(1-.8*spWeight)`；`edge=v>0 ? a*(1+range) : a`；`mask=smoothstep(0,range,-uv.y+edge+curve)`（UV.y=0 是底部）。因此上升与回撤的软边和弧度可逆，速度变化确实影响边界。

这是原站场景合成的复刻基准。本站用它揭示同一面有实体厚度、砖缝和侧光的墙；墙组的上移距离由视口与实体构图确定，在同一 reveal 通道中校准。原先任意 `.65/.85` 三段时点不再作为默认。白墙落定后停止吸附和镜头控制，正文和 Giscus 正常滚动；原站的平灰亮场色不替换本站既定墙材。

指针流体的活跃路径已核对，完整求解及玻璃关系见 [流体来源报告](iterations/evidence/alche-motion-2026-10-08/source-fluid-report.txt)。T03.05 按以下基准复现，单独验收，不用任意粒子拖尾替代。

| 流体对象 | 复刻基准 |
| --- | --- |
| 尺寸与场 | 长边 256、短边按视口比取整；RGBA 保存 xy 速度/z 压力/w 散度，线性采样；没有另一个彩色染料场 |
| 输入 | 位置 L(raw,1)，其追随残差再 L(error,2)；signedPow(残差,1.6) 累积到每轴 ±1 的 buffer，求解后 buffer 每帧乘 .5 |
| 注入 | buffer 乘 30，按 aspect 修正后每轴限 ±2；局部半径 `.01+.1*min(.5,smoothstep(.01,1,length(buffer)))`，单位是视口长边；原站 `pointerSize=.1` 未使用 |

#### 9.3.6 消除侧视光片的连续光晕（39轮）

2026-10-10用户指出旋转侧面出现“两个光片”，要求光晕晕开。[用户原图](iterations/evidence/u03-p01-2026-10-10-39-design/user-light-sheets.png)否定的是光的空间形态。现有makeHalo在正反Z平面沿XY延展DoubleSide光带，仅改Gaussian不会消除侧视的片状结构。37轮的柔光方向保留，其几何实现由本节替换。

- **首样机制：**撤除前后平面向外扩展的光带，复用真实实体几何及现有表面受光作为独立发光源。优先低分辨率局部发光mask→屏幕空间连续模糊→柔和合成，光域由投影后的可见实体驱动；不对整页/背景曲线/文字做泛光。边缘受光需覆盖Z方向侧面，不能只画两条正反端线。优先复用已安装Three的HorizontalBlurShader、VerticalBlurShader与FullScreenQuad；具体管线见39轮任务。
