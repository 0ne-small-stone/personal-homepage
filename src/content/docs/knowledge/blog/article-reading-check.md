## 从一个入口开始

资料、文章和笔记放在同一个知识库里。资料保留教材、讲义或阅读材料，笔记保存学习过程，文章则用连续的文字说明一个问题。学习总览按类型筛选这三种内容；文章列表按日期展示文章。

这份样稿的标题含有“博客阅读验证”。在搜索中输入这几个字，就能找到同一篇正文。搜索结果也可能定位到一个小节，进入后的地址会带上对应的章节锚点。

阅读时可以先看目录，再选择关心的部分。桌面目录放在正文旁，手机目录使用框架原生的展开入口。章节链接可以单独分享；直接打开文章地址也能读到完整内容。

## 把阅读过程写清楚

一篇文章可以先提出问题，再说明采用的材料、过程和结论。段落围绕同一个意思展开；如果只是记录一个还没有想清楚的问题，也可以先保存成笔记。

下面这组条目仅用来观察普通 Markdown 的呈现：

1. 写下想解决的问题，限定讨论范围。
2. 阅读资料，记下来源和仍不确定的地方。
3. 用自己的话组织说明，保留必要的引用链接。
4. 回看结论能否由前面的材料支持。

> 一个可以被读者核对的说明，需要让读者找到材料，并分清事实、推断和仍待验证的部分。

这里的内容是功能验证示例。网页编辑、图片上传和正式发布会分别在后续迭代中实现、验证，不由这份正文样稿代替验收。

## 阅读代码片段

代码块沿用现成渲染器，支持横向滚动与复制。可以复制下面这段 JavaScript，观察复制后的文字是否与代码一致：

```js
const readingTypes = ['资料', '文章', '笔记'];
console.log(readingTypes.join(' / '));
```

代码字体使用等宽回退，中文正文使用苹方优先字体栈。设备没有苹方时会采用本机可用的回退字体；页面不会为这份样稿下载整套中文字体。
